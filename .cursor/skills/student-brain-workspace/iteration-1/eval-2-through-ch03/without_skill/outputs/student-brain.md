## Chapter 01 개론 (`01-intro.md`)

### 학습 목표
- C언어 특징·학습 방향 이해
- 컴파일 기반 언어의 학습 흐름 파악

목표 자체는 읽을 수 있음. “컴파일” 단어는 아직 모름 → 본문에서 나올 듯.

### c언어의 특징
읽음.
- C = 컴퓨터에게 일 시키는 방법을 기초부터 배우는 언어.
- 메모리·주소·데이터 저장 방식을 직접 다룬다 → “메모리”, “주소”가 정확히 뭔진 모르지만, 지금은 “컴퓨터 안쪽을 더 자세히 본다” 정도로 받아들임.
- 처음엔 부담될 수 있다. 나중에 C++/C#/Java에 기초가 된다.
- 화려한 결과보다 동작 원리를 정확히.

내 생각: OK. 왜 C를 배우는지 대충 감 옴. 메모리·주소는 나중에 더 나와야 할 듯.

### 컴파일이란
읽음.
- 소스 코드(`.c`) → 실행 파일(`.exe`)로 바꾸는 과정.
- 사람 언어를 컴퓨터가 이해하는 형태로 번역.
- 흐름: 코드 작성 → 컴파일 → 실행.
- 문법 틀리면 오류, 실행 파일 안 만들어질 수 있음.

내 생각: 이해됨. “번역” 비유 좋음. 파이썬처럼 바로 실행이 아니라 먼저 번역이 필요하다는 뜻으로 잡음.

### c언어의 탄생 배경과 활용 분야
읽음.
- 1970년대 벨 연구소, 시스템 소프트웨어.
- UNIX, 임베디드, 드라이버, 게임 엔진 코어.
- 성능·제어가 중요할 때.
- 게임 개발 목표면 성능·메모리 개념에 도움.

내 생각: 배경 스토리로 받아들임. “임베디드”, “드라이버”는 잘 모르지만 지금은 “컴퓨터 깊숙한 쪽 프로그램” 정도로 넘어감. 멈춰야 할 정도는 아님.

### Visual Studio란?
읽음.
- Microsoft IDE = 통합 개발 환경.
- 작성·빌드(컴파일)·실행·오류 확인·디버깅을 한곳에서.
- 프로그래밍 작업실 비유.
- 이 과정에서 코드 쓰는 자리 + MSVC 컴파일러 중심 도구.

내 생각: IDE가 “도구 모음 프로그램”이라는 건 이해. “디버깅”은 “문제 추적”이라고 적혀 있어서 OK. MSVC는 다음 절에서.

### `cl`이란?
읽음.
- Visual Studio 안 MSVC 컴파일러를 명령줄에서 쓸 때 이름.
- `main.c` → 실행 가능한 프로그램.
- `main.obj`(중간), `main.exe`(실행)가 생길 수 있음.
- 이 문서는 Windows + Visual Studio + `cl` 기준.

내 생각: `cl` = 번역해 주는 프로그램 이름. `.obj`가 “기계어에 가까운 중간”이라는데, 기계어가 뭔진 흐릿하지만 “완성 전 중간 파일”로 넘김.

### IDE를 쓰면 `cl`을 직접 몰라도 되나요?
읽음.
- 빌드 버튼이 내부에서 `cl` 호출.
- 일상은 IDE, 원리는 “컴파일러가 소스를 실행 파일로 바꾼다”만 알면 됨.

내 생각: 안심됨. 버튼으로도 된다.

### 개발환경 세팅하기 (STEP 1~5)
읽음.
- Community 설치 → Installer → Desktop development with C++ 체크.
- MSVC, Windows SDK, CMake tools 포함 확인.
- Developer PowerShell for VS 2022 사용 (일반 PowerShell 아님).
- `cl` 입력해서 버전·도움말 나오면 OK.
- 안 되면 워크로드·셸·재부팅 점검.

내 생각: 설치 절차는 따라 할 수 있을 듯. “CMake tools”가 뭔진 모르지만 체크리스트 항목으로만 봄. 지금은 설치 가이드로 이해.

### 첫 c 소스 파일 생성하기
읽음.
```c
#include <stdio.h>
int main(void) {
    printf("Hello, C!\n");
    return 0;
}
```
- `#include <stdio.h>` = 화면 출력에 필요한 선언 가져옴.
- `#`으로 시작 = 전처리기. 세부는 뒤 챕터.
- `main` = 프로그램 입구.

내 생각:
- 코드를 그대로 따라 쓰면 된다는 느낌.
- “전처리기”는 모름 → 문서가 “뒤에 다시”라고 해서 지금은 보류.
- `printf`, `return 0`은 아직 왜인진 모르지만 다음에 나올 듯.
- `\n`도 아직 설명 없음. 연습문제에서 줄바꿈이라고 나올 듯.

여기서는 “지금은 형태만 따라 한다”로 넘김. 완전 이해는 아님. 다만 문서가 뒤를 예고해서 **학습 중단까지는 안 함**.

### cli로 컴파일하고 실행하기
읽음.

- 옵션 `/Fe`, `/W4` 표 있음. 옵션 = 추가 지시.
- `.\` = 지금 폴더에서 실행.
- 자주 막힘: 일반 PowerShell, 워크로드 누락.

내 생각: 명령 순서 이해됨. 표의 `/W4` Warning 수준도 “경고 더 보기”로 OK.

### 비주얼 스튜디오에서 바로 컴파일하고 실행하기
읽음. Ctrl+Shift+B, Ctrl+F5 등.

내 생각: CLI랑 같은 목표, 다른 버튼. OK.

### 연습문제·정답 포인트
읽음. printf 문자열 바꾸기, `\n` 줄바꿈, CLI+IDE 둘 다 실행.

내 생각: 연습은 “따라 하면 됨” 수준으로 보임. Ch01 완료로 표시.

**Ch01 요약 (내 말로):** C는 원리 중심 언어. 소스→컴파일→실행. VS/`cl`로 환경 잡고 Hello 찍기.

목표 이해됨.

### 02-1 Hello World! 출력해보기
예제 읽음. Ch01이랑 비슷. `int main()`에 `(void)` 없음 → 작은 차이는 있는데 지금은 “둘 다 main”으로 넘김.

#### `main` 함수: 프로그램의 출발점
- 실행 시 항상 `main`부터.
- `main`은 함수(이름 붙은 작업 묶음).
- 함수 자세한 건 곧 나온다고 함.

작은 `main`만 있는 예: `return 0;`만.

내 생각: “시작점 = main” 명확. 좋음.

#### 조금 더 자세히 알아보기
- `int` = integer = 정수. 함수 이름 앞에 **결과값 자료형**을 적는다.
- `float`·`double`·`char`는 Ch03에서.
- `{ }` = 함수 내용 범위.
- `return` = 돌려줄 값. 반환.
- `;` = 문장 끝.

내 생각:
- “함수가 결과값을 가진다”는 수학 함수 느낌으로 대충 OK.
- 그런데 `main`이 `printf`만 하고 `return 0`이면… 0이 “결과”인가? 정상 종료 숫자 같기도 하고. 문장이 “돌려줄 값”이라고만 해서 **완전히 맑진 않음**.
- 그래도 다음 절에서 함수를 더 푼다고 해서 계속 읽음.

#### ‘함수’는 어떤 의미일까요?
- 수학 함수와 비슷: 일 하고 결과 가능.
- C는 화면 출력 같은 **동작**도 함. 100% 같진 않음.
- 지금은 입력 → 계산 → 결과 순서로 연습.

내 생각: OK. 비유 도움이 됨.

#### `main` 말고 다른 함수도 만들 수 있나요?
- 가능. `helper` 예제.
- 자동 시작은 `main`뿐. 다른 함수는 `main` 안에서 이름 불러야 함 = 함수 호출.

```c
helper();
```

내 생각: “불러서 실행” 그림이 그려짐. 주석에 “만들기기” 오타 같지만 학습엔 지장 없음.

#### 수학의 함수 `f(x)`처럼 매개변수
```c
int f(int x) {
    return 3 * x + 4;
}
...
f(0);
```
- `int x` = 입력, 매개변수(parameter).
- C는 자료형을 함수·매개변수 앞에 적어야 함. 컴퓨터가 타입을 미리 알게.

내 생각:
- `f(0)` 하면 결과가 4일 것 같은데… **화면에 안 나옴**. return만 하고 printf 없음.
- “돌려준다”가 어디로 가는지 아직 흐릿.
- 그래도 “입력 x를 받아서 계산한다”는 이해. 중단할 정도는 아님.

#### printf를 안 만들었는데 어떻게 쓰나?
- `printf`도 누가 미리 정해 둔 함수.
- 정보가 헤더 파일(`.h`)에 있음.
- `#include` = 다른 파일 내용 읽어 넣기.
- `stdio.h` = 표준 입출력. `printf` 선언(“이렇게 호출 가능” 안내).
- 없으면 빨간줄·컴파일 에러.

내 생각: “가져다 쓴다”로 이해. “선언”이 실제 코드 전체가 아니라 “안내”라는 점이 신기하지만 문장상 따라감.

#### 코드를 다시 읽기
네 줄 요약: include → main → printf 호출 → return 0 정상 종료.

내 생각: Ch01 예제가 이제 조금 더 읽힘. `return 0` = 정상 종료라는 말도 여기서 연결됨. 앞에서 흐릿했던 게 좀 풀림.

#### 자주 하는 실수
세미콜론 빠짐, `main` 이름 바꾸기 금지.

OK.

## Chapter 03 변수와 연산자 (`03-variables-operators.md`)

### 학습 목표
- 변수 선언과 값 저장
- 기본 연산자와 입력 함수

목표 문장은 읽힘. “입력 함수”는 아직 안 배움.

### 03-1 변수란?
읽음.
- 변수 = 값이 들어가는 **이름 붙은 상자**.
- 처음 값 넣기 = **초기화**.
- 초기화 안 하면 나중에 “쓰레기값” 문제.
- 이름은 의미가 드러나게.

내 생각: 상자 비유 좋음. “쓰레기값”은 이상한 이름이지만 “아무 값이나 들어 있는 상태” 예고로 이해 시도.

#### 변수 타입(자료형) 기본 — 여기서 멈춤

첫 문단:
> C 언어는 **자료형(type, 타입)**으로 “이 변수에 어떤 종류의 값이 들어가는지”를 미리 정합니다.

여기까지 OK. Ch02에서 int/float/char 미리보기도 있었음.

그다음이 어려움:
> 아래는 표준 C에서 정의되는 **대표적인 기본 자료형**을 입문 관점에서만 묶은 표입니다. **용량(바이트)** 열은 변수 하나가 메모리에서 차지하는 공간을 **바이트(byte)** 단위로 본 **예**이며, **일반적인 Windows + MSVC 64비트** 조합에서 자주 보이는 값입니다. 표준은 `int`·`long` 등 **정수형 하나가 몇 바이트인지**까지는 고정하지 않아, **구현(컴파일러·대상 CPU·데이터 모델)마다** 달라질 수 있습니다. **`long`만 그런 것이 아니라 `int`도 마찬가지**이고, 다만 요즘 PC용 32·64비트 환경에서는 `int`가 4 bytes인 경우가 매우 흔합니다. Linux·다른 컴파일러·32비트 빌드에서는 표에 적은 숫자와 다를 수 있으므로, 확실히 알고 싶을 때는 뒤에서 배우는 `sizeof`로 직접 확인하는 습관이 좋습니다.

## 학습 중단

**중단 위치:** `docs/c/03-variables-operators.md` → `### 03-1 변수란?` → `#### 변수 타입(자료형) 기본` 도입 문단 (자료형 표에 들어가기 직전~표 설명 문장)

**무엇을 모르는지:**
1. **바이트(byte)**가 정확히 무엇인지. “용량”, “메모리에서 차지하는 공간”이라고만 나오는데, 메모리를 공간으로 잰다는 감각이 없음. Ch01에서 메모리·주소를 “내부 동작”으로만 듣고 끝남.
2. **구현(컴파일러·대상 CPU·데이터 모델)** 단어들. 컴파일러는 Ch01에서 “번역 도구”로 알았는데, “구현마다 크기가 다르다”, “데이터 모델”은 처음 보는 말.
3. 같은 `int`인데 **4 bytes가 ‘흔하다’**는 말과 **표준은 고정하지 않는다**는 말이 한꺼번에 나와서, “그러면 나는 뭘 외워야 하지?”가 안 정해짐.
4. 바로 이어질 표에 `unsigned`, `void`, `void*`, `bool`, `long double` 등이 보일 것 같은데, 도입 문단부터 이미 과함.

**왜 어려운지:**
- 변수 = 상자까지는 비유로 따라왔음.
