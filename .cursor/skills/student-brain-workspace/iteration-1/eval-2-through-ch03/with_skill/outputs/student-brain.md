- **컴파일**은 사람이 읽기 쉬운 소스 코드(`.c`)를 컴퓨터가 실행할 수 있는 형태(Windows에서는 보통 `.exe`)로 바꾸는 과정이고, 번역에 가깝다고 했다. 흐름은 `코드 작성 → 컴파일 → 실행`이다. 문법이 틀리면 오류가 나고 실행 파일이 안 만들어질 수 있다고 했다.
- C는 1970년대 벨 연구소에서 나왔고, 운영체제·임베디드·드라이버·게임 엔진 코어처럼 성능·제어가 중요한 곳에서 쓰인다고 했다. 단어는 낯설지만 “성능이 중요한 곳” 정도로만 잡았다.
- **Visual Studio**는 Microsoft의 **IDE**(통합 개발 환경)이고, 코드 작성·빌드·실행·오류 확인·디버깅을 한 화면에서 하게 해 준다고 했다. 프로그래밍 작업실 비유는 괜찮았다.
- **`cl`**은 Visual Studio에 들어 있는 MSVC 컴파일러를 명령줄에서 부를 때 쓰는 이름이라고 했다. `main.c` 같은 소스를 실행 파일로 만들어 준다고 했다. 끝나면 `main.obj`와 `main.exe`가 생길 수 있다고 했다. 이 문서는 Windows + Visual Studio + `cl` 기준이라고 했다.
- IDE 빌드 버튼이 안에서 `cl`을 대신 부를 수 있어서, 매번 명령을 직접 안 쳐도 학습은 된다고 했다. 그래도 “컴파일러가 소스를 실행 파일로 바꾼다”는 그림은 알아 두라고 했다.
- 설치 STEP 1~5: Community 설치 → **Desktop development with C++** 워크로드 → **Developer PowerShell for VS 2022** → `cl` 입력해 확인 → 안 되면 워크로드·셸·재부팅 점검. 일반 PowerShell이 아니라 개발자용 셸을 써야 한다고 이해했다.
- 프로젝트 폴더에 `main.c`를 둔다고 했다. `#include <stdio.h>`는 화면 출력에 필요한 선언을 가져오는 줄이고, `#`으로 시작하는 줄은 전처리기인데 세부는 뒤 챕터라고 해서 “지금은 가져오는 줄” 정도로만 두기로 했다. `main`은 프로그램이 시작되는 **입구**라고 했다.
