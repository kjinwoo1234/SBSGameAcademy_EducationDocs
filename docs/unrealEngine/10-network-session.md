# Chapter 10 네트워크 세션

## 학습 목표

- 세션 생성과 참가의 역할을 구분할 수 있다.
- 세션 API 호출 순서와 콜백 처리 흐름을 설명할 수 있다.
- 로비에서 플레이 맵으로 가는 최소 흐름을 실습으로 확인할 수 있다.

## 본문

### 10-1 세션이란

**세션**은 “함께 플레이할 방”을 온라인 서브시스템이 찾아주고 붙이게 하는 단위입니다. LAN·Steam·EOS 등 서브시스템에 따라 API 세부는 다르지만, 학습 흐름은 같습니다.

1. 호스트가 세션을 **생성**한다.
2. 다른 플레이어가 세션을 **검색·참가**한다.
3. 준비되면 모두 같은 **플레이 레벨**로 이동한다.

로컬 연습만 할 때는 Listen Server로 맵을 바로 열어도 되지만, “방 만들기/참가” UX를 배우려면 세션 API를 씁니다.

### 10-2 생성과 참가

| 단계 | 하는 일 |
|---|---|
| Create Session | 방 이름·공개 여부·최대 인원 설정 후 생성 |
| Find Sessions | 검색 결과 목록 요청 |
| Join Session | 선택한 결과로 접속 |
| Destroy Session | 호스트 종료 시 정리 |

개념 코드 골격입니다. 실제 클래스는 프로젝트의 Online Subsystem·세션 인터페이스에 맞게 맞춥니다.

```cpp
// 호스트
SessionInterface->CreateSession(LocalPlayerNum, SessionName, SessionSettings);
// 성공 콜백에서 로비 UI 갱신 또는 Travel 준비

// 게스트
SessionInterface->FindSessions(LocalPlayerNum, SearchSettings);
// 결과 목록을 UI에 표시한 뒤
SessionInterface->JoinSession(LocalPlayerNum, SessionName, SearchResult);
```

성공 콜백에서 UI를 갱신하고, 실패 시 이유를 로그로 남깁니다. 서브시스템 null, 네트워크 권한, 중복 생성이 흔한 실패 원인입니다. 세션 로직을 위젯 Tick에 넣지 마세요.

### 10-3 레벨 이동

세션에 모인 뒤 **로비 레벨**에 있다가 **게임 레벨**로 `ServerTravel` 하는 패턴이 많습니다. 호스트가 여행을 시작하면 참가자도 따라갑니다.

주의할 점:

- 여행 전에 필요한 액터·클래스가 양쪽 패키지에 있는가
- GameMode가 게임 레벨에 맞게 설정됐는가
- 로컬 PIE 테스트와 실제 서브시스템 테스트는 환경이 다름

### 10-4 따라하기 — 세션 생성·참가

1. 로비 맵과 게임 맵을 나눈다.
2. 로비 UI에 방 만들기·새로고침·참가·게임 시작 버튼을 둔다.

![로비 위젯: 방 만들기·새로고침·참가·게임 시작 버튼이 배치된 UMG 디자이너 화면](./img/10-lobby-session-ui.png)

3. 방 만들기 → Create Session 성공 로그를 확인한다.
4. PIE 플레이어 2, Listen Server로 실행한다. 한쪽은 생성, 다른쪽은 Find→Join을 시도한다.
5. Join 성공 후 두 창이 같은 로비에 있는지 확인한다.
6. 호스트만 ServerTravel로 게임 맵에 들어가고, 게스트도 따라가는지 확인한다.
7. 실패 시 서브시스템 이름·에러 코드를 로그에 남긴다.

LAN·Null 서브시스템으로 먼저 성공시킨 뒤, Steam 등 외부 서브시스템은 환경이 준비됐을 때 같은 흐름으로 바꾼다.

체력·발사 복제는 아직 이 장 범위가 아닙니다. 방이 만들어지고 같은 맵에 입장하는 것까지 확인한 뒤 Chapter 11로 갑니다.

### 연습문제

1. 문제: 세션 생성과 세션 참가를 호스트/게스트 기준으로 한 줄씩 쓰세요.  
2. 문제: 로비 레벨과 게임 레벨을 나누는 이유를 한 문장으로 쓰세요.  
3. 문제: Join이 실패했을 때 로그에 남기면 좋은 정보 하나를 드세요.

### 정답 포인트
