# Chapter 05 게임 기획·구현

## 학습 목표

- 조작·규칙·피드백을 짧은 기획으로 문서화할 수 있다.
- 일정을 주차 단위로 나누고 구현 순서를 정할 수 있다.
- 기획에 맞춰 기존 FPS에 기능을 선택적으로 확장할 수 있다.

## 본문

### 05-1 무엇을 기획하는가

이 주는 새 엔진 기능을 잔뜩 넣는 주가 아닙니다. **이미 만든 FPS**를 재미 있게 다듬기 위해 범위를 정합니다.

최소 기획 항목은 아래를 채웁니다.

| 항목 | 적을 내용 예 |
|---|---|
| 플레이어 조작 | 이동, 조준, 발사, 재장전 여부 |
| 게임 규칙 | 목표 점수, 제한 시간, 생명 |
| 사운드 | 발사음, 명중음, 배경음 유무 |
| 이펙트 | 총구 화염, 히트 스파크 |
| UI | 체력, 점수, 남은 시간 |
| 게임플레이 | 적 종류 수, 스폰 방식 |

한 주에 다 넣지 않습니다. **Must / Should / Could**로 나눕니다. Must만 이번 주에 코드로 옮깁니다.

### 05-2 일정 수립

학습 순서상 다음으로 AI, 그다음 내비, 그다음 통합이 이어집니다. 기획서에 대략 이렇게 적을 수 있습니다.

1. 지금: Must 규칙·UI·사운드 중 선택 구현
2. 다음: 추적 AI
3. 그다음: NavMesh로 이동 품질
4. 통합: 체력·데미지 오브젝트·이펙트 정리

일정은 “하고 싶은 것”이 아니라 **플레이 가능한 빌드**가 단계마다 남게 잡습니다.

### 05-3 컴포넌트로 나누어 구현

언리얼에서는 기능을 액터에 모두 몰기보다 **컴포넌트**로 나누면 재사용이 쉽습니다. 예를 들어 체력만 담당하는 컴포넌트, 발사만 담당하는 컴포넌트입니다.

구현 순서는 보통 다음과 같습니다.

1. 규칙에 필요한 데이터부터 정한다. 예: `WinScore`, `MaxHealth`
2. 데이터가 바뀌는 코드 경로를 연결한다. 예: 처치 → 점수
3. 플레이어가 보게 피드백을 붙인다. 사운드·이펙트·UI
4. 조작 불편만 최소 수정한다

사운드는 `UAudioComponent` 또는 `UGameplayStatics::PlaySoundAtLocation`으로 한 줄 재생부터 시작합니다. 이펙트는 나이아가라·캐스케이드 중 프로젝트에 있는 쪽으로 히트 지점에 스폰합니다. 세부 FX 파이프라인은 Chapter 08에서 다시 묶습니다.

이 장 산출물은 **한 장짜리 기획**과 **Must 항목의 동작하는 빌드**입니다. AI는 Chapter 06으로 미룹니다.

### 05-4 따라하기 — 기획서·FPS 확장

1. Must / Should / Could 표를 한 장으로 적는다.
2. Must만 골라 기존 FPS에 붙일 순서를 번호로 적는다.
3. Must 중 하나 이상을 구현해 플레이 가능한 빌드를 남긴다.
4. 사운드 또는 UI 피드백을 최소 하나 연결한다.
5. Could 항목은 목록에만 남기고 코드에 넣지 않는다.

### 연습문제

1. 문제: 자신의 FPS Must 항목 3개를 목록으로 쓰세요.  
2. 문제: Could로 미룰 기능 하나를 고르고 이유를 한 문장으로 쓰세요.  
3. 문제: “매주 플레이 가능한 빌드”가 중요한 이유를 한 문장으로 쓰세요.

### 정답 포인트

- Must는 규칙·조작·최소 피드백. Could는 장식·2번째 무기 등. 매주 실행 가능해야 다음 주 AI·통합에 이어짐.
