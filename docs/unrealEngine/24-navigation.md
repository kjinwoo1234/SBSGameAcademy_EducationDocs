# Chapter 24 내비게이션

## 학습 목표

- 내비 메시를 빌드하고 걸을 수 있는 영역을 화면에서 확인할 수 있다.
- 블루프린트와 C++에서 내비게이션으로 캐릭터를 이동시킬 수 있다.
- 내비 모디파이어 볼륨과 내비 링크 프록시의 쓰임을 구분해 배치할 수 있다.
- 게임 중 지형이 바뀔 때 내비 메시를 갱신하는 방법을 설명할 수 있다.

## 본문

### 24-1 내비 메시

Chapter 23에서 적이 목적지까지 벽을 돌아 걸어갔습니다. 목적지까지 가는 길을 찾는 일을 **길찾기**라고 하고, 언리얼의 **내비게이션 시스템**이 담당합니다.

길을 찾으려면 먼저 어디가 걸을 수 있는 곳인지 알아야 합니다. 엔진이 레벨을 분석해 걸을 수 있는 바닥을 계산해 둔 데이터를 **내비 메시**라고 합니다.

1. 액터 배치 패널의 **볼륨**에서 **내비 메시 바운드 볼륨**을 레벨에 놓는다.
2. `R`을 눌러 AI가 다닐 구역 전체를 덮도록 키운다.
3. 뷰포트에서 `P`를 누른다.

![레벨 뷰포트에 내비 메시 바운드 볼륨과 초록색 내비 메시 영역이 표시된 화면](./img/24-navmesh-bounds-visualization.png)

초록색으로 칠해진 곳이 걸을 수 있는 영역입니다. 볼륨 밖은 계산하지 않으므로 초록색이 없고, AI는 그곳으로 갈 수 없습니다. 벽이나 가구 주변은 캐릭터의 몸 두께만큼 비워져 있습니다. 문틈이 캐릭터보다 좁거나 계단이 너무 가파르면 초록색이 끊깁니다.

내비게이션 시스템은 길을 찾는 것뿐 아니라 그 길의 길이도 알려 줍니다. 레이싱 게임에서 결승점까지 남은 거리를 계산하는 데에도 쓸 수 있습니다.

### 24-2 블루프린트로 이동시키기

비헤이비어 트리 없이 블루프린트 노드만으로도 내비게이션 이동을 시킬 수 있습니다.

`BP_Enemy`의 이벤트 그래프에서 해 봅니다. Chapter 23의 트리와 겹치지 않도록 AI 컨트롤러 클래스를 잠시 기본 `AIController`로 바꿔 둡니다.

1. `Event BeginPlay`에 `AI MoveTo` 노드를 연결한다.
2. **Pawn**에 `Self` 노드를 연결한다.
3. **Target Actor**에 `Get Player Character` 노드를 연결한다.
4. 플레이한다.

**AI MoveTo**는 폰을 목적지나 대상 액터까지 내비 메시를 따라 이동시키는 노드입니다. 실행 출력 핀이 **On Success**와 **On Fail**로 나뉘어 있어서 도착했을 때와 실패했을 때 다른 동작을 이을 수 있습니다. 비헤이비어 트리의 `Move To` 태스크도 안에서 같은 일을 합니다.

적이 한 번만 쫓아오고 멈춥니다. 플레이어가 움직여도 계속 쫓게 하려면 **On Success**와 **On Fail** 뒤에 `Delay` 노드를 두고 다시 `AI MoveTo`로 연결합니다.

### 24-3 C++에서 이동시키기

C++에서 내비게이션과 AI 기능을 쓰려면 해당 모듈을 프로젝트에 추가해야 합니다. `Source/Practice/Practice.Build.cs` 파일을 열어 모듈 목록에 두 이름을 추가합니다.

```csharp
PublicDependencyModuleNames.AddRange(new string[] {
	"Core", "CoreUObject", "Engine", "InputCore", "EnhancedInput",
	"NavigationSystem", "AIModule"
});
```

`Build.cs`는 이 프로젝트가 엔진의 어떤 모듈을 쓰는지 적어 두는 파일입니다. 목록에 없는 모듈의 헤더를 포함하면 빌드 오류가 납니다. 파일을 고친 뒤에는 에디터를 닫고 빌드합니다.

플레이어 캐릭터를 지정한 위치로 걸어가게 하는 코드입니다.

```cpp
#include "Blueprint/AIBlueprintHelperLibrary.h"

void AMyCharacter::MoveToPoint(const FVector& Destination)
{
	UAIBlueprintHelperLibrary::SimpleMoveToLocation(GetController(), Destination);
}
```

`SimpleMoveToLocation(컨트롤러, 목적지)`는 그 컨트롤러가 조종하는 폰을 목적지까지 내비 메시를 따라 이동시킵니다. 마우스로 클릭한 곳으로 캐릭터가 걸어가는 조작을 만들 때 씁니다.

두 지점 사이의 길 길이를 구하는 코드입니다.

```cpp
#include "NavigationSystem.h"
#include "NavigationPath.h"

float AMyCharacter::GetPathLengthTo(const FVector& Destination)
{
	UNavigationPath* Path = UNavigationSystemV1::FindPathToLocationSynchronously(
		this, GetActorLocation(), Destination);

	if (Path != nullptr && Path->IsValid())
	{
		return Path->GetPathLength();
	}

	return -1.0f;
}
```

**코드 해석**

- `FindPathToLocationSynchronously(기준 객체, 출발, 도착)`은 길을 찾아 경로 객체를 돌려줍니다.
- `IsValid()`는 길을 찾았는지 알려 줍니다. 내비 메시가 끊겨 갈 수 없으면 거짓입니다.
- `GetPathLength()`는 벽을 돌아가는 실제 이동 거리입니다. 두 점 사이의 직선 거리와 다릅니다.
- 길이 없을 때는 `-1`을 돌려주어 호출한 쪽이 구분할 수 있게 했습니다.

### 24-4 내비 모디파이어 볼륨

길이 열려 있어도 가능하면 피해 가게 하고 싶은 곳이 있습니다. 불이 붙은 바닥이나 독 늪 같은 곳입니다.

**내비 모디파이어 볼륨**은 상자 안쪽의 내비 메시 성질을 바꾸는 액터입니다. 디테일 패널의 **영역 클래스**로 어떻게 바꿀지 정합니다.

| 영역 클래스 | 효과 |
|---|---|
| `NavArea_Null` | 그 영역의 내비 메시를 없앤다. 절대 지나가지 않는다 |
| `NavArea_Obstacle` | 지나가는 비용을 크게 높인다. 다른 길이 있으면 돌아간다 |

**비용**은 길찾기가 그 구간을 얼마나 꺼리는지를 나타내는 값입니다. 길찾기는 거리가 아니라 비용의 합이 가장 작은 길을 고릅니다. 비용이 높은 영역은 조금 멀더라도 돌아가고, 다른 길이 없으면 그대로 지나갑니다.

볼륨을 통로 한가운데에 놓고 `P`로 확인하면 그 부분의 색이 달라지거나 비어 있습니다.

### 24-5 내비 링크 프록시

2층 난간에서 1층으로 뛰어내리는 길은 내비 메시가 끊겨 있어서 길찾기가 쓰지 못합니다. **내비 링크 프록시**는 떨어진 두 지점을 "여기서 저기로 갈 수 있다"고 이어 주는 액터입니다.

1. 액터 배치 패널에서 **내비 링크 프록시**를 찾아 끊긴 곳 근처에 놓는다.
2. 액터를 선택하면 보이는 두 개의 점을 각각 위층 가장자리와 아래층 바닥으로 옮긴다.
3. 디테일 패널의 **포인트 링크 → 방향**을 정한다.

![층간 낭떠러지에 내비 링크 프록시를 배치해 위·아래 내비 메시를 이은 레벨 화면](./img/24-nav-link-proxy.png)

| 방향 | 의미 |
|---|---|
| Both Ways | 양쪽 모두 이동할 수 있다 |
| Left to Right | 한쪽에서 다른 쪽으로만 이동할 수 있다 |

뛰어내릴 수는 있지만 올라올 수 없는 곳은 한 방향으로 설정합니다.

레벨이 크면 링크를 일일이 놓기 어렵습니다. 최신 엔진 버전에는 내비 메시를 만들 때 낭떠러지 같은 곳에 링크를 자동으로 만들어 주는 옵션이 있습니다. 레벨에 자동으로 생긴 `RecastNavMesh` 액터를 선택하고 디테일 패널에서 내비 링크 생성 관련 옵션을 켭니다. 옵션 이름과 위치는 버전마다 다릅니다.

### 24-6 게임 중 내비 메시 갱신

에디터에서 만든 내비 메시는 지형이 변하지 않는 레벨에 맞습니다. 게임 중에 문이 열리거나 벽이 부서지면 걸을 수 있는 영역이 달라지는데, 내비 메시는 그대로라서 AI가 열린 문을 지나가지 못합니다.

게임 중에도 내비 메시가 다시 계산되게 하려면 설정을 바꿉니다.

1. **편집 → 프로젝트 세팅 → 엔진 → 내비게이션 메시**를 연다.
2. **런타임 → 런타임 생성**을 `Dynamic`으로 바꾼다.

| 런타임 생성 | 동작 |
|---|---|
| Static | 게임 중 다시 계산하지 않는다. 가장 가볍다 |
| Dynamic Modifiers Only | 모디파이어로 인한 변화만 반영한다 |
| Dynamic | 물체가 움직이면 주변을 다시 계산한다. 가장 무겁다 |

움직이는 물체가 내비 메시에 영향을 주려면 그 물체의 컴포넌트에서 **내비게이션에 영향 가능**이 켜져 있어야 합니다. 다시 계산하는 일은 비용이 크므로, 꼭 필요한 레벨에서만 `Dynamic`을 씁니다.

처음에는 고정된 레벨에서 추격과 순찰을 안정시킨 뒤, 문 하나로 갱신을 실험하는 순서를 권합니다.

### 24-7 이동이 안 될 때 확인 순서

1. `P`로 내비 메시가 출발지와 목적지를 모두 덮는지 본다.
2. 폰에 AI 컨트롤러가 빙의해 있는지 본다.
3. 목적지 액터나 위치 값이 비어 있지 않은지 본다.
4. 통로 폭이 캐릭터 캡슐보다 넓은지 본다.

### 24-8 따라하기 — AI와 내비게이션

1. 내비 메시 바운드 볼륨으로 레벨을 덮고 `P`로 확인한다.
2. `AI MoveTo`로 적이 플레이어를 계속 쫓아오게 만든다.
3. `Build.cs`에 모듈을 추가하고 `GetPathLengthTo`를 만든다. `Tick`에서 레벨의 한 지점까지의 길 길이를 로그로 찍어, 벽 뒤로 돌아갈 때 값이 어떻게 변하는지 본다.
4. 통로에 내비 모디파이어 볼륨을 놓고 영역 클래스를 `NavArea_Obstacle`로 해서 적이 돌아가는지 확인한다.
5. 높은 발판을 만들고 내비 링크 프록시로 아래와 이어 적이 뛰어내려 쫓아오게 한다.
6. AI 컨트롤러 클래스를 `BP_EnemyController`로 되돌려 Chapter 23의 트리가 같은 레벨에서 동작하는지 확인한다.

### 정답 포인트

- 볼륨 밖에는 내비 메시가 없어 AI가 그곳으로 가지 못한다. Null은 절대 지나가지 않고, Obstacle은 비용이 높아 가능하면 돌아간다. 내비게이션 메시의 런타임 생성을 `Dynamic`으로.
