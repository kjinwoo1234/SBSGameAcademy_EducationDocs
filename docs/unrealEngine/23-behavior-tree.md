# Chapter 23 비헤이비어 트리

## 학습 목표

- 블랙보드와 비헤이비어 트리의 역할을 구분할 수 있다.
- AI 컨트롤러가 폰을 조종하며 비헤이비어 트리를 실행하는 구조를 설명할 수 있다.
- 추격과 순찰을 오가는 트리를 셀렉터·시퀀스·데코레이터로 구성할 수 있다.
- 실행 중인 트리를 보며 동작하지 않는 지점을 찾을 수 있다.

## 본문

### 23-1 적에게 판단을 넣는 방법

지금 레벨에 놓인 적 캐릭터는 가만히 서서 맞기만 합니다. 적이 플레이어를 보면 쫓아오고, 놓치면 돌아다니게 만들려면 "지금 무엇을 할지" 판단하는 장치가 필요합니다.

블루프린트의 Tick에 조건 검사를 줄줄이 넣어도 만들 수 있지만, 행동이 늘어날수록 조건이 얽혀 고치기 어려워집니다. 언리얼은 AI의 판단을 나무 모양 그래프로 그리는 도구를 제공합니다.

| 에셋 | 역할 |
|---|---|
| 블랙보드 | AI가 기억하는 값을 이름과 함께 적어 두는 메모판 |
| 비헤이비어 트리 | 메모판의 값을 보고 어떤 행동을 어떤 순서로 할지 정하는 그래프 |

**블랙보드**에는 "쫓을 대상", "순찰할 위치", "적이 보이는가" 같은 값을 둡니다. 값 하나를 **키**라고 부릅니다. **비헤이비어 트리**는 그 키를 읽어 행동을 고릅니다.

### 23-2 AI 컨트롤러

Chapter 16에서 폰을 조종하는 주체가 컨트롤러라고 했습니다. 사람이 조종하면 플레이어 컨트롤러, 컴퓨터가 조종하면 **AI 컨트롤러**입니다. 비헤이비어 트리는 AI 컨트롤러가 실행합니다.

적 캐릭터와 AI 컨트롤러를 준비합니다.

1. `BP_ThirdPersonCharacter`를 복제해 `BP_Enemy`를 만든다.
2. 콘텐츠 브라우저에서 블루프린트 클래스를 만들 때 **모든 클래스**에서 `AIController`를 찾아 부모로 고르고, 이름을 `BP_EnemyController`로 짓는다.
3. `BP_Enemy`의 **클래스 디폴트**에서 **폰 → AI 컨트롤러 클래스**를 `BP_EnemyController`로 바꾼다.
4. 같은 곳의 **AI 자동 빙의**가 `Placed in World or Spawned`인지 확인한다.

**AI 자동 빙의**는 이 폰이 레벨에 놓이거나 생성될 때 AI 컨트롤러가 자동으로 빙의하게 하는 설정입니다. 같은 캐릭터 클래스라도 플레이어 컨트롤러가 빙의하면 플레이어가 되고 AI 컨트롤러가 빙의하면 적이 됩니다.

### 23-3 블랙보드와 비헤이비어 트리 만들기

1. 콘텐츠 브라우저를 우클릭해 **인공지능 → 블랙보드**를 만들고 이름을 `BB_Enemy`로 짓는다.
2. `BB_Enemy`를 열어 **새 키**로 아래 세 개를 만든다.

| 키 이름 | 키 타입 | 용도 |
|---|---|---|
| `EnemyActor` | Object. 베이스 클래스를 Actor로 | 쫓을 대상 |
| `HasLineOfSight` | Bool | 대상이 보이는가 |
| `PatrolLocation` | Vector | 순찰할 위치 |

3. **인공지능 → 비헤이비어 트리**를 만들고 이름을 `BT_Enemy`로 짓는다.
4. `BT_Enemy`를 열고 디테일 패널의 **블랙보드 에셋**이 `BB_Enemy`인지 확인한다.
5. `BP_EnemyController`의 이벤트 그래프에서 `Event On Possess`에 `Run Behavior Tree` 노드를 연결하고 **BTAsset**을 `BT_Enemy`로 고른다.

**Event On Possess**는 컨트롤러가 폰에 빙의한 순간 실행됩니다. 이때부터 트리가 돌기 시작합니다.

### 23-4 트리의 노드 종류

비헤이비어 트리는 맨 위 **Root**에서 시작해 아래로, 같은 높이에서는 왼쪽에서 오른쪽으로 실행됩니다.

| 노드 | 역할 |
|---|---|
| 셀렉터 | 자식을 왼쪽부터 시도해 하나가 성공하면 멈춘다. 여러 행동 중 하나를 고를 때 쓴다 |
| 시퀀스 | 자식을 왼쪽부터 차례로 실행하고 하나가 실패하면 멈춘다. 순서대로 해야 하는 행동에 쓴다 |
| 태스크 | 실제 행동. 이동, 대기, 공격 |
| 데코레이터 | 노드에 붙이는 조건. 조건이 맞을 때만 그 노드가 실행된다 |
| 서비스 | 노드에 붙여 일정 간격으로 값을 갱신한다 |

셀렉터와 시퀀스는 직접 행동하지 않고 자식의 실행 흐름을 정합니다. 태스크는 실행 후 성공 또는 실패를 부모에게 알립니다.

![비헤이비어 트리 에디터: Root 아래 셀렉터, 그 아래 추격 시퀀스와 순찰 시퀀스가 배치된 레이아웃](./img/23-behavior-tree-layout.png)

### 23-5 순찰 만들기

먼저 아무 곳이나 돌아다니는 순찰부터 만듭니다. 갈 위치를 무작위로 골라 블랙보드에 적는 태스크가 필요합니다.

1. 비헤이비어 트리 에디터 위쪽 **새 태스크**를 누르고 `BTTask_BlueprintBase`를 고른다. 이름을 `BTT_FindRandomPatrol`로 짓는다.
2. 변수 `PatrolLocationKey`를 추가한다. 타입은 **Blackboard Key Selector**이고 **인스턴스 편집가능**에 체크한다.
3. 이벤트 그래프에서 **Event Receive Execute AI**를 만든다.
4. 이벤트의 **Controlled Pawn**에서 `Get Actor Location`을 꺼낸다.
5. `Get Random Reachable Point In Radius` 노드의 **Origin**에 그 위치를 연결하고 **Radius**에 `1000`을 넣는다.
6. `Set Blackboard Value as Vector` 노드의 **Key**에 `PatrolLocationKey`를, **Value**에 5번의 결과 위치를 연결한다.
7. 마지막에 `Finish Execute` 노드를 연결하고 **Success**에 체크한다.

**Get Random Reachable Point In Radius**는 기준 위치 주변에서 걸어서 갈 수 있는 임의의 지점을 돌려줍니다. 태스크는 반드시 `Finish Execute`로 끝났다고 알려야 트리가 다음 노드로 넘어갑니다.

트리를 구성합니다.

8. `BT_Enemy`에서 Root 아래로 선을 끌어 **셀렉터**를 만든다.
9. 셀렉터 아래에 **시퀀스**를 만들고 이름을 `Patrol`로 바꾼다.
10. 시퀀스 아래에 왼쪽부터 `BTT_FindRandomPatrol`, `Move To`, `Wait` 태스크를 만든다.
11. `BTT_FindRandomPatrol`을 선택하고 디테일 패널의 **Patrol Location Key**를 `PatrolLocation`으로 고른다.
12. `Move To`의 **블랙보드 키**를 `PatrolLocation`으로 고른다.
13. `Wait`의 **대기 시간**을 `4`로 한다.

AI가 걸어 다니려면 걸을 수 있는 영역 정보가 필요합니다. 액터 배치 패널의 **볼륨**에서 **내비 메시 바운드 볼륨**을 놓고 바닥 전체를 덮도록 키웁니다. 뷰포트에서 `P`를 누르면 걸을 수 있는 영역이 초록색으로 보입니다. 이 볼륨이 하는 일은 Chapter 24에서 자세히 다룹니다.

`BP_Enemy`를 레벨에 놓고 플레이하면 적이 임의의 위치로 걸어가 4초 쉬기를 반복합니다.

### 23-6 플레이어 감지

적이 플레이어를 볼 수 있어야 쫓아갈 수 있습니다. AI 컨트롤러에 감각 기관 역할의 컴포넌트를 붙입니다.

1. `BP_EnemyController`에 **AIPerception** 컴포넌트를 추가한다.
2. 디테일 패널의 **감각 환경설정**에 `+`로 항목을 추가하고 **AI 시야 환경설정**을 고른다.
3. **소속별 탐지**의 적, 중립, 아군에 모두 체크한다.
4. 컴포넌트의 이벤트 항목에서 **On Target Perception Updated** 옆 `+`를 누른다.
5. 이벤트의 **Actor**를 플레이어 캐릭터 클래스로 캐스트한다.
6. 캐스트 성공 시 **Stimulus** 핀을 **구조체 핀 분할**해서 나오는 **Successfully Sensed** 값을 확인한다.
7. `Get Blackboard` 노드에서 `Set Value as Bool`을 꺼내 **Key Name**에 `HasLineOfSight`를 적고 6번 값을 넣는다.
8. `Set Value as Object`로 **Key Name** `EnemyActor`에 5번의 캐릭터를 넣는다.

**On Target Perception Updated**는 무언가가 시야에 들어오거나 벗어날 때 실행됩니다. **Successfully Sensed**가 참이면 방금 보이기 시작한 것이고 거짓이면 방금 놓친 것입니다.

### 23-7 추격 만들기

1. `BT_Enemy`의 셀렉터 아래, `Patrol` 시퀀스의 **왼쪽**에 시퀀스를 하나 더 만들고 이름을 `Chase Player`로 바꾼다.
2. `Chase Player` 시퀀스를 우클릭해 **데코레이터 추가 → Blackboard**를 누른다.
3. 데코레이터를 선택하고 **블랙보드 키**를 `HasLineOfSight`, **키 쿼리**를 `Is Set`으로 한다.
4. **관찰자 중단**을 `Both`로 바꾼다.
5. `Chase Player` 아래에 `Move To` 태스크를 만들고 **블랙보드 키**를 `EnemyActor`로 고른다.

셀렉터는 왼쪽부터 시도하므로, 플레이어가 보이면 추격 시퀀스가 실행되고 보이지 않으면 데코레이터에 막혀 오른쪽 순찰 시퀀스로 넘어갑니다.

**관찰자 중단**은 조건이 바뀌었을 때 하던 일을 끊을지 정합니다. `Both`로 두면 순찰하러 걸어가는 도중에도 플레이어가 보이는 순간 순찰을 멈추고 추격으로 넘어가고, 추격 중 놓치면 추격을 멈춥니다. `None`이면 하던 행동이 끝날 때까지 기다립니다.

### 23-8 실행 중인 트리 확인하기

기대한 대로 움직이지 않을 때는 트리가 지금 어느 노드를 실행하고 있는지 봅니다.

1. 플레이를 시작한 뒤 `BT_Enemy` 에디터 창을 연다.
2. 지금 실행 중인 노드가 강조되고, 선을 따라 흐름이 표시된다.
3. 오른쪽 아래 **블랙보드** 패널에서 키의 현재 값을 본다.

![플레이 중 비헤이비어 트리 창에서 실행 중인 태스크가 강조되고 블랙보드 키 값이 표시된 화면](./img/23-bt-debug-active-node.png)

자주 만나는 문제와 확인할 곳입니다.

| 증상 | 확인할 곳 |
|---|---|
| 트리 창에 아무 노드도 강조되지 않는다 | `BP_Enemy`의 AI 컨트롤러 클래스, `Run Behavior Tree` 연결 |
| 추격 시퀀스로 들어가지 않는다 | 블랙보드의 `HasLineOfSight` 값, 감지 이벤트의 캐스트 성공 여부 |
| `Move To`에서 멈춰 있다 | 내비 메시 바운드 볼륨이 출발지와 목적지를 덮는지 |
| 순찰이 시작되자마자 끊긴다 | 데코레이터의 관찰자 중단 설정 |

### 23-9 따라하기 — 추격하고 순찰하는 적

1. `BP_Enemy`와 `BP_EnemyController`를 만들고 연결한다.
2. `BB_Enemy`에 키 세 개를 만들고 `BT_Enemy`를 실행하게 한다.
3. `BTT_FindRandomPatrol`과 순찰 시퀀스를 만든다.
4. 내비 메시 바운드 볼륨을 놓고 순찰이 되는지 확인한다.
5. AIPerception으로 플레이어를 감지해 블랙보드 값을 채운다.
6. 추격 시퀀스와 데코레이터를 추가한다.
7. 플레이 중 트리 창을 열어 추격과 순찰이 전환되는 것을 확인한다.
8. `Chase Player` 시퀀스의 `Move To` 뒤에 `Wait` 1초를 추가해, 플레이어에게 닿은 뒤 잠시 멈추게 한다.

### 연습문제

1. 문제: 블랙보드와 비헤이비어 트리의 역할을 한 줄씩 쓰세요.
2. 문제: 셀렉터와 시퀀스의 차이를 두 문장으로 쓰세요.  
   - 조건: 자식이 성공했을 때와 실패했을 때를 각각 언급할 것
3. 문제: 추격 시퀀스를 순찰 시퀀스의 왼쪽에 두는 이유를 한 문장으로 쓰세요.

### 정답 포인트

- 블랙보드는 AI가 기억하는 값의 저장소, 비헤이비어 트리는 그 값으로 행동을 정하는 그래프. 셀렉터는 하나가 성공하면 멈추고, 시퀀스는 하나가 실패하면 멈춘다. 셀렉터가 왼쪽부터 시도하므로 추격을 순찰보다 먼저 검사하게 하려고.
