# Chapter 18 애니메이션 블루프린트와 스테이트 머신

## 학습 목표

- 애님 인스턴스와 애님 그래프의 역할을 구분할 수 있다.
- 애니메이션 블루프린트를 만들어 캐릭터에 적용할 수 있다.
- 스테이트 머신과 트랜지션 룰로 멈춤과 달리기 애니메이션을 전환할 수 있다.
- 컨듀잇과 스테이트 에일리어스로 스테이트 머신을 정리할 수 있다.

## 본문

### 18-1 애니메이션 블루프린트

캐릭터는 서 있을 때, 달릴 때, 점프할 때 서로 다른 동작을 보여 줘야 합니다. 동작 하나를 담은 에셋을 **애니메이션 시퀀스**라고 합니다. 문제는 지금 어떤 시퀀스를 재생해야 하는지를 누가, 어떻게 정하느냐입니다.

**애니메이션 블루프린트**는 캐릭터의 상태를 보고 지금 보여 줄 동작을 정하는 전용 블루프린트입니다. 두 부분으로 이루어져 있습니다.

| 부분 | 역할 | 만드는 방법 |
|---|---|---|
| 애님 인스턴스 | 캐릭터의 정보를 읽어 변수에 담아 둔다 | 블루프린트의 이벤트 그래프 또는 C++ |
| 애님 그래프 | 변수 값에 따라 어떤 동작을 낼지 설계한다 | 블루프린트로만 |

애님 인스턴스가 "지금 속도가 얼마다"라는 정보를 준비하면, 애님 그래프가 그 정보를 보고 "그러면 달리기 동작"이라고 정하는 구조입니다.

캐릭터처럼 뼈대가 있어서 동작을 재생할 수 있는 모형을 **스켈레탈 메시**라고 하고, 그 뼈대 구조를 담은 에셋을 **스켈레톤**이라고 합니다. 애니메이션 시퀀스와 애니메이션 블루프린트는 특정 스켈레톤에 맞춰 만들어집니다.

### 18-2 애님 인스턴스 클래스와 블루프린트 만들기

나중에 C++ 코드와 연결하기 위해 C++ 애님 인스턴스 클래스를 먼저 만듭니다.

1. **툴 → 새 C++ 클래스**에서 **모든 클래스**를 펼쳐 `AnimInstance`를 찾아 부모로 고른다.
2. 이름을 `MyAnimInstance`로 짓고 빌드한다.

애니메이션 블루프린트를 만듭니다.

3. 콘텐츠 브라우저를 우클릭해 **애니메이션 → 애니메이션 블루프린트**를 누른다.
4. 스켈레톤 선택 창에서 템플릿 캐릭터의 스켈레톤 `SK_Mannequin`을 고른다.
5. 이름을 `ABP_MyAnim`으로 짓고 연다.
6. 위쪽 **클래스 세팅**을 누르고 디테일 패널의 **부모 클래스**를 `MyAnimInstance`로 바꾼다.

![애니메이션 블루프린트 에디터: 왼쪽 프리뷰, 가운데 애님 그래프의 Output Pose 노드, 오른쪽 아래 애셋 브라우저](./img/18-anim-blueprint-editor.png)

### 18-3 애니메이션 하나 재생하기

애니메이션 블루프린트 에디터의 **애님 그래프** 탭에는 **Output Pose** 노드가 하나 있습니다. 이 노드의 **Result** 핀에 연결된 동작이 최종적으로 캐릭터에 재생됩니다.

1. 에디터 오른쪽 아래 **애셋 브라우저**에서 앞으로 달리는 시퀀스를 찾는다. 이름은 엔진 버전에 따라 `MM_Run_Fwd`, `MF_Run_Fwd` 등으로 다르다.
2. 시퀀스를 애님 그래프로 끌어다 놓는다.
3. 생긴 노드의 출력 핀을 `Output Pose`의 `Result`에 연결한다.
4. 컴파일한다. 왼쪽 프리뷰의 캐릭터가 달린다.

캐릭터에 적용합니다.

5. 3인칭 캐릭터 블루프린트를 열고 컴포넌트 탭에서 **메시**를 선택한다.
6. 디테일 패널의 **애니메이션 → 애님 클래스**를 `ABP_MyAnim`으로 바꾼다.
7. 플레이한다.

캐릭터가 가만히 있어도 달리는 동작을 하다가 한 번 재생이 끝나면 멈춥니다. 애님 그래프에서 시퀀스 노드를 선택하고 디테일 패널의 **애니메이션 루프**에 체크하면 계속 반복됩니다.

### 18-4 스테이트 머신

가만히 있을 때는 서 있는 동작을, 움직일 때는 달리는 동작을 보여 줘야 합니다. 캐릭터가 처할 수 있는 상황을 나눠 놓고 상황 사이를 오가게 만드는 도구가 **스테이트 머신**입니다.

| 용어 | 의미 |
|---|---|
| 스테이트 | 상황 하나. 스테이트마다 재생할 동작이 하나 정해져 있다 |
| Entry | 스테이트 머신이 처음 시작하는 지점 |
| 트랜지션 | 한 스테이트에서 다른 스테이트로 넘어가는 화살표 |
| 트랜지션 룰 | 트랜지션을 넘어가도 되는 조건 |

만드는 순서입니다.

1. 애님 그래프에서 기존 시퀀스 노드를 지운다.
2. 우클릭해 **State Machine**을 검색해 만든다.
3. 스테이트 머신 노드를 `Output Pose`의 `Result`에 연결한다.
4. 스테이트 머신 노드를 더블클릭해 안으로 들어간다.
5. `Entry`에서 선을 끌어 빈 곳에 놓고 **스테이트 추가**를 고른다. 이름을 `Idle`로 짓는다.
6. `Idle`의 테두리에서 선을 끌어 스테이트를 하나 더 만들고 이름을 `Run`으로 짓는다.
7. `Run`의 테두리에서 `Idle`로 선을 끌어 반대 방향 화살표도 만든다.
8. `Idle`을 더블클릭해 들어가서 멈춤 시퀀스를 `Output Animation Pose`에 연결한다. 시퀀스 이름은 `MM_Idle` 등이다.
9. `Run`에도 같은 방법으로 달리기 시퀀스를 연결하고 애니메이션 루프에 체크한다.

![스테이트 머신 그래프: Entry → Idle ⇄ Run 두 스테이트와 양방향 트랜지션 화살표](./img/18-state-machine-idle-run.png)

컴파일하면 프리뷰에서 `Idle` 스테이트가 강조되어 보입니다. 스테이트 머신은 Entry에서 시작해 지금 스테이트를 정하고, 그 스테이트 안에 연결된 동작을 애님 그래프로 내보냅니다. 아직 트랜지션 룰이 비어 있어서 `Run`으로 넘어가지 못합니다.

### 18-5 캐릭터 무브먼트 가져오기

트랜지션 룰에서 캐릭터가 움직이는지 확인하려면 캐릭터의 속도를 알아야 합니다. 속도는 캐릭터 무브먼트 컴포넌트가 가지고 있으므로, 이 컴포넌트를 변수에 담아 둡니다.

애니메이션 블루프린트의 **이벤트 그래프** 탭으로 갑니다.

1. 내 블루프린트 탭에서 변수를 추가하고 이름을 `MovementComponent`로 짓는다. 변수 타입은 **캐릭터 무브먼트 컴포넌트**의 **오브젝트 레퍼런스**로 한다.
2. 그래프에서 우클릭해 **Event Blueprint Initialize Animation** 이벤트를 만든다.
3. `Get Owning Actor` 노드를 만든다.
4. 그 출력을 `Cast To Character` 노드에 연결하고, 이벤트의 실행 핀도 연결한다.
5. 캐스트 노드의 **As Character** 핀에서 `Character Movement`를 꺼낸다.
6. `Set MovementComponent` 노드에 연결한다.

![애니메이션 블루프린트 이벤트 그래프: Event Blueprint Initialize Animation → Get Owning Actor → Cast To Character → Character Movement → Set MovementComponent](./img/18-anim-event-graph-movement.png)

| 노드 | 역할 |
|---|---|
| Event Blueprint Initialize Animation | 애님 인스턴스가 만들어질 때 한 번 실행된다 |
| Get Owning Actor | 이 애니메이션 블루프린트를 쓰고 있는 액터를 가져온다 |
| Cast To Character | 그 액터가 캐릭터인지 확인하고 캐릭터로 바꿔 다룬다 |

애니메이션 블루프린트의 이벤트는 엔진이 정해진 때에 불러 주는 함수입니다. C++에서 가상 함수를 재정의하는 것과 같습니다. 매 프레임 실행되는 **Event Blueprint Update Animation**도 있으며, 매 프레임 바뀌는 값을 변수에 담을 때 씁니다.

### 18-6 트랜지션 룰

이제 조건을 채웁니다.

1. 스테이트 머신으로 돌아가 `Idle`에서 `Run`으로 가는 화살표의 동그란 아이콘을 더블클릭한다.
2. 안에 `Result` 노드가 하나 있다. **Can Enter Transition** 핀에 참이 전달되면 넘어간다.
3. `Get MovementComponent`를 만들고 그 핀에서 `Velocity`를 꺼낸다.
4. `Velocity`를 `Is Nearly Zero (Vector)` 노드에 연결한다.
5. 그 결과를 `NOT Boolean` 노드에 연결하고 `Result`에 연결한다.

**Velocity**는 캐릭터가 지금 움직이는 방향과 빠르기를 담은 벡터입니다. **Is Nearly Zero**는 벡터의 크기가 거의 `0`이면 참을 돌려줍니다. 정확히 `0`인지 비교하지 않고 **Tolerance**에 적힌 오차 범위 안이면 `0`으로 봅니다.

멈춰 있으면 참, 움직이면 거짓이 나오는데, `Run`으로 넘어가는 조건은 "움직일 때"이므로 **NOT** 노드로 뒤집습니다. NOT은 C++의 `!`와 같습니다.

6. `Run`에서 `Idle`로 가는 화살표에는 같은 노드를 만들되 NOT 없이 `Is Nearly Zero`를 바로 `Result`에 연결한다.

컴파일하고 플레이합니다. 가만히 있으면 서 있는 동작, 움직이면 달리는 동작이 재생됩니다.

### 18-7 컨듀잇

스테이트가 `Idle`과 `Run`뿐일 때는 화살표를 더블클릭해 조건을 확인하면 됩니다. 스테이트가 늘어나면 어떤 화살표가 무슨 조건인지 하나씩 열어 봐야 알 수 있어 번거로워집니다.

**컨듀잇**은 조건에 이름을 붙여 그래프 위에 보이게 놓는 노드입니다. 안쪽은 트랜지션 룰과 똑같이 생겼습니다.

1. 스테이트 머신 그래프에서 우클릭해 **컨듀잇 추가**를 누르고 이름을 `IsMoving`으로 짓는다.
2. 컨듀잇을 더블클릭해 들어가 18-6의 움직임 조건을 `Result`에 연결한다.
3. `Idle`에서 `IsMoving`으로, `IsMoving`에서 `Run`으로 화살표를 잇는다.
4. `IsMoving`으로 들어가고 나가는 화살표의 트랜지션 룰은 `Result`의 체크박스에 체크해 항상 참으로 둔다.

![Idle → IsMoving 컨듀잇 → Run 으로 연결된 스테이트 머신 그래프](./img/18-conduit.png)

조건 검사는 컨듀잇이 하므로 앞뒤 화살표에는 조건을 따로 넣지 않습니다. 그래프만 봐도 "움직이면 달리기로 간다"는 것이 읽힙니다.

### 18-8 스테이트 에일리어스

스테이트가 여덟 개쯤 되고 서로 오갈 수 있게 화살표를 모두 그리면 그래프가 선으로 뒤덮입니다. 예를 들어 어느 스테이트에서든 사망 스테이트로 갈 수 있어야 한다면, 모든 스테이트에서 사망으로 화살표를 그려야 합니다.

**스테이트 에일리어스**는 다른 스테이트를 대신하는 바로가기입니다. 윈도우의 바로가기 아이콘이 실제 파일은 아니지만 누르면 그 파일이 열리는 것과 같습니다.

1. 스테이트 머신 그래프에서 우클릭해 **스테이트 에일리어스 추가**를 누른다.
2. 에일리어스를 선택하면 디테일 패널에 이 스테이트 머신의 모든 스테이트 목록이 체크박스로 나온다.
3. 대신할 스테이트에 체크한다. 여러 개를 체크할 수 있다.
4. 에일리어스에서 목적지 스테이트로 화살표를 긋는다.

`Idle`과 `Run`에 체크한 에일리어스에서 `Dead` 스테이트로 화살표를 하나 그으면, `Idle`에서 `Dead`로, `Run`에서 `Dead`로 각각 그은 것과 똑같이 동작합니다. 에일리어스는 화살표가 나가는 쪽뿐 아니라 들어오는 쪽으로도 쓸 수 있습니다.

### 18-9 따라하기 — 멈춤과 달리기

1. `MyAnimInstance` C++ 클래스와 `ABP_MyAnim`을 만들고 부모 클래스를 연결한다.
2. 달리기 시퀀스 하나만 재생해 캐릭터에 적용되는지 확인한다.
3. 스테이트 머신에 `Idle`과 `Run`을 만든다.
4. 이벤트 그래프에서 `MovementComponent` 변수를 채운다.
5. 두 방향의 트랜지션 룰을 채우고 플레이한다.
6. `Idle`에서 `Run`으로 가는 조건을 컨듀잇 `IsMoving`으로 옮긴다.
7. 참·거짓 변수 `bIsMoving`을 만들고, `Event Blueprint Update Animation`에서 매 프레임 값을 계산해 담은 뒤 트랜지션 룰과 컨듀잇에서는 이 변수만 읽도록 바꾼다.

7번처럼 계산은 이벤트 그래프에서 하고 애님 그래프에서는 변수만 읽는 방식이 실제 프로젝트에서 많이 쓰는 구조입니다. 18-1에서 설명한 애님 인스턴스와 애님 그래프의 역할 분담과 맞습니다.

### 연습문제

1. 문제: 애님 인스턴스와 애님 그래프의 역할을 한 줄씩 쓰세요.
2. 문제: `Idle`에서 `Run`으로 가는 트랜지션 룰에 NOT 노드가 필요한 이유를 한 문장으로 쓰세요.  
   - 조건: `Is Nearly Zero`가 돌려주는 값을 언급할 것
3. 문제: 스테이트 다섯 개 모두에서 `Dead` 스테이트로 갈 수 있게 하려면 화살표를 다섯 개 그리는 대신 무엇을 쓰면 되는지 쓰세요.

### 정답 포인트

- 애님 인스턴스는 캐릭터 정보를 변수에 준비하고, 애님 그래프는 그 변수로 재생할 동작을 정한다. `Is Nearly Zero`는 멈췄을 때 참이므로 움직일 때 참이 되게 뒤집어야 한다. 스테이트 에일리어스.
