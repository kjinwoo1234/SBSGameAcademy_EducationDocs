# Chapter 16 서버 모델·게임 플로우

## 학습 목표

- 리슨 서버와 전용 서버의 차이를 설명할 수 있다.
- 접속부터 플레이까지 네트워크 플로우를 단계로 그릴 수 있다.
- PIE 리슨 서버로 멀티플레이 실습을 진행할 수 있다.

## 본문

### 16-1 리슨 서버와 전용 서버

| 모델 | 특징 | 수업·소규모 |
|---|---|---|
| **리슨 서버** | 플레이어 한 명이 서버+클라이언트 | PIE·친구와 빠른 테스트에 적합 |
| **전용 서버** | 플레이 없는 서버 프로세스 | 경쟁·안정성·헤드리스 운영 |

리슨 서버는 호스트 PC가 시뮬레이션도 하므로 호스트가 유리하거나, 호스트가 나가면 방이 깨질 수 있습니다. 전용 서버는 설정·배포가 더 필요합니다.

이 과정 실습의 기본은 **리슨 서버**입니다.

### 16-2 접속부터 플레이까지

한 줄 플로우는 다음과 같습니다.

1. 실행 → 로비 UI
2. 호스트 Create Session / 게스트 Find·Join
3. 같은 로비 레벨에서 대기
4. 호스트가 게임 레벨로 Travel
5. GameMode가 폰 스폰, PlayerState 준비
6. 입력 → Server RPC → 복제된 체력·점수 → UI
7. 승패 조건 → 결과 UI → 세션 정리 또는 로비 복귀

앞 장에서 배운 조각을 이 순서에 끼워 넣으면 “네트워크 FPS 한 판”이 됩니다.

### 16-3 리슨 서버 실습 절차

1. 에디터 Play 설정에서 플레이어 수를 2 이상으로 둔다.
2. Net Mode를 Listen Server로 둔다.

![Chapter 09와 동일 계열: Play 설정의 Players·Net Mode와 PIE 창 두 개 배치](./img/16-pie-listen-server-checklist.png)

3. 호스트 창과 클라이언트 창에서 이동이 서로 보이는지 확인한다.
4. 발사·체력·점수가 양쪽에서 같은지 확인한다.
5. 한쪽에만 보이는 FX가 있다면 Multicast·스폰 권한을 점검한다.

실제 Steam 등 서브시스템 접속은 패키지·권한·앱 ID 설정이 더 필요합니다. 수업 마무리는 PIE 리슨 서버로 플로우가 끊기지 않는 것을 목표로 합니다.

이 장으로 커리큘럼 5~6개월 네트워킹 학습을 닫습니다.

### 연습문제

1. 문제: 리슨 서버와 전용 서버의 차이를 두 문장으로 쓰세요.  
2. 문제: 접속→플레이 플로우를 다섯 단계 이내 목록으로 쓰세요.  
3. 문제: PIE 2인에서 체력이 한쪽만 줄어들 때 먼저 볼 것 두 가지를 쓰세요.
