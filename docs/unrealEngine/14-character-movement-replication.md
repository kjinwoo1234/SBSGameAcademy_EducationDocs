# Chapter 14 캐릭터·이동 리플리케이션

## 학습 목표

- 네트워크 캐릭터에서 이동이 기본적으로 어떻게 동기화되는지 설명할 수 있다.
- 소유 클라이언트와 시뮬레이트 프록시의 이동 차이를 구분할 수 있다.
- 이동이 어긋질 때 확인할 설정 항목을 나열할 수 있다.

## 본문

### 14-1 CharacterMovement와 복제

`ACharacter`의 **Character Movement**는 멀티플레이에서 이동 복제 지원이 비교적 잘 갖춰져 있습니다. 템플릿 캐릭터를 쓰면 기본 이동은 창 간에 보이는 경우가 많습니다.

직접 `SetActorLocation`만 Tick에서 돌리면 복제·보정과 충돌하기 쉽습니다. 네트워크 캐릭터는 가능하면 이동 컴포넌트와 입력 경로를 유지합니다.

### 14-2 소유자와 시뮬레이트

- **소유 클라이언트**: 입력을 넣고, 예측 이동 후 서버 보정
- **서버**: 권한 있는 위치·속도 확정
- **다른 클라이언트**: 복제된 이동을 보간·시뮬레이트

텔레포트·대시처럼 특수 이동은 서버에서 위치를 바꾸고 복제되게 설계합니다. 로컬만 `SetActorLocation`하면 남에게 안 보입니다.

### 14-3 점검 목록

이동이 한쪽만 보이거나 미끄러우면 다음을 봅니다.

1. 캐릭터·이동 컴포넌트 복제 관련 기본 설정
2. 입력이 로컬 컨트롤러에서만 들어오는지
3. 서버 여행 후 Possess가 올바른 폰에 붙었는지
4. 충돌·내비와 무관한지. 순수 네트워크 문제인지 분리

세션·역할 장은 앞 장에서 다뤘습니다. 이 장은 **캐릭터가 같이 걸어 보이는가**에 집중합니다. 로비 UI와 점수는 Chapter 15입니다.

### 14-4 따라하기 — 멀티 캐릭터 이동

1. PIE 플레이어 2, Listen Server로 실행한다.
2. 호스트·클라이언트가 각각 걸어 양쪽 창에 보이는지 확인한다.
3. Tick `SetActorLocation` 이동이 있으면 CharacterMovement 경로로 되돌린다.
4. 대시·텔레포트가 있으면 서버에서 위치를 바꾸는지 확인한다.
5. 위 점검 목록 네 항을 통과시킨다.

### 연습문제

1. 문제: Tick에서 `SetActorLocation`만으로 멀티 이동을 구현할 때 위험한 이유를 한 문장으로 쓰세요.  
2. 문제: 다른 플레이어 캐릭터가 Simulated Proxy일 때 입력을 직접 넣지 않는 이유를 한 문장으로 쓰세요.  
3. 문제: 대시를 서버에서 처리해야 하는 이유를 한 문장으로 쓰세요.

### 정답 포인트

- 복제·보정과 충돌. Simulated는 남 캐릭터. 위치 권한은 서버.
