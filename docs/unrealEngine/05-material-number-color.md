# Chapter 05 머티리얼 — 수와 색

## 학습 목표

- 0과 1 사이의 수가 색에 어떻게 대응되는지 설명할 수 있다.
- 스칼라와 벡터를 구분하고 머티리얼 노드로 만들 수 있다.
- Add와 Multiply가 색을 어떻게 바꾸는지 예측할 수 있다.
- HSV 색상 모델로 보색·유사색을 계산하는 머티리얼을 만들 수 있다.

## 본문

### 05-1 수를 색으로 본다

Chapter 04에서는 노드를 순서대로 연결해 결과만 얻었습니다. 이 장부터는 그 노드들이 실제로 무엇을 계산하는지 배웁니다.

컴퓨터는 색을 숫자로 다룹니다. 가장 어두운 검정을 `0`, 가장 밝은 흰색을 `1`로 정하고, 그 사이의 회색을 `0`과 `1` 사이의 수로 나타냅니다. `0.5`는 딱 중간 밝기의 회색입니다.

실제 화면은 가로 1920칸일 수도 있고 3840칸일 수도 있습니다. 화면마다 계산을 다르게 하면 번거롭기 때문에, 먼저 `0`에서 `1` 범위로 줄여 계산하고 마지막에 화면 크기만큼 늘립니다. 이렇게 값의 범위를 `0`에서 `1`로 맞추는 일을 **정규화**라고 합니다. 머티리얼에서 다루는 색과 좌표는 대부분 정규화된 값입니다.

### 05-2 실습용 머티리얼 준비

수와 색의 관계만 깨끗하게 보기 위해, 빛의 영향을 받지 않는 화면용 머티리얼로 실습합니다.

1. Chapter 04에서 만든 `M_MyMaterial`을 열고 결과 노드를 뺀 나머지 노드를 지운다.
2. 그래프 빈 곳을 클릭하고 디테일 패널의 **머티리얼 도메인**을 `User Interface`로 바꾼다.
3. 결과 노드의 입력이 **최종 색**을 포함한 몇 개로 줄어드는 것을 확인한다.
4. `1`을 누른 채 클릭해 상수 노드를 만들고 값을 `1`로 바꾼다.
5. 상수 노드를 **최종 색**에 연결한다.

미리보기가 흰색으로 바뀝니다. 값을 `0.5`로 바꾸면 회색, `0`으로 바꾸면 검정이 됩니다. 한 번 정하면 실행 중에 바뀌지 않는 값이라서 이 노드를 **상수** 노드라고 부릅니다.

값을 `-3`이나 `5`처럼 범위 밖으로 넣어 보세요. `0`보다 작으면 검정, `1`보다 크면 흰색으로 보입니다. 머티리얼 안에서는 어떤 수든 계산할 수 있지만, 마지막에 화면에 그릴 때는 `0`에서 `1` 사이만 표현됩니다.

### 05-3 스칼라와 벡터

회색이 아닌 색을 만들려면 수 하나로는 부족합니다. 컴퓨터는 빨강, 초록, 파랑 세 가지 빛을 섞어 모든 색을 만듭니다. 영어 첫 글자를 따서 **RGB**라고 합니다. 색 하나를 정하려면 빨강의 양, 초록의 양, 파랑의 양 세 개의 수가 필요합니다.

여러 개의 수를 한 묶음으로 다루는 값을 **벡터**라고 합니다. 수가 몇 개 묶였는지에 따라 2차원 벡터, 3차원 벡터, 4차원 벡터라고 부릅니다. 묶이지 않은 수 하나는 벡터와 구분해 **스칼라**라고 합니다.

| 노드 | 단축키 | 값의 종류 | 주로 담는 것 |
|---|---|---|---|
| 상수 | `1` + 클릭 | 스칼라 | 밝기, 세기 |
| 상수 2 벡터 | `2` + 클릭 | 2차원 벡터 | 평면 위의 좌표 |
| 상수 3 벡터 | `3` + 클릭 | 3차원 벡터 | RGB 색 |
| 상수 4 벡터 | `4` + 클릭 | 4차원 벡터 | RGB 색과 투명도 |

수학 시간에 배운 좌표 `(x, y, z)`와 색 `(r, g, b)`는 이름만 다를 뿐 수 세 개의 묶음이라는 점에서 같습니다. 그래서 같은 3차원 벡터 노드로 좌표도 색도 담을 수 있습니다.

`3`을 누른 채 클릭해 노드를 만들고 더블클릭하면 색 선택 창이 열립니다. 창에 표시되는 R, G, B 값이 모두 `0`에서 `1` 사이인 것을 확인하세요. 그림 프로그램에서 `0`부터 `255`로 쓰던 색 값이 언리얼에서는 정규화되어 있습니다.

### 05-4 디버그 노드로 값 확인하기

노드 결과가 색으로만 보이면 정확한 숫자를 알기 어렵습니다. 값을 숫자로 찍어 보여 주는 **디버그 노드**를 씁니다.

| 노드 | 보여 주는 값 |
|---|---|
| `DebugScalarValues` | 스칼라 1개 |
| `DebugFloat3Values` | 3차원 벡터의 세 수 |

그래프를 우클릭해 `debug`로 검색하면 나옵니다. 확인할 값을 디버그 노드에 연결하고, 디버그 노드를 최종 색에 연결하면 미리보기에 숫자가 표시됩니다.

노드가 많아지면 볼 때마다 최종 색에 다시 연결하기 번거롭습니다. 디버그 노드를 우클릭하고 **노드 프리뷰 시작**을 누르면 그 노드가 파랗게 바뀌고, 최종 색에 연결하지 않아도 미리보기에 그 노드의 결과가 나옵니다. 끝나면 다시 우클릭해 **노드 프리뷰 중지**를 누릅니다.

![DebugFloat3Values 노드에 노드 프리뷰를 켜서 미리보기 창에 RGB 세 값이 숫자로 표시된 화면](./img/05-debug-node-preview.png)

### 05-5 더하기와 곱하기

두 수를 받아 하나의 결과를 내는 계산을 머티리얼에서도 노드로 합니다.

| 노드 | 단축키 | 계산 |
|---|---|---|
| `Add` | `A` + 클릭 | A + B |
| `Multiply` | `M` + 클릭 | A × B |

`0.5` 회색에 `0.25`를 **더하면** `0.75`가 되어 밝아집니다. 더하기는 수직선 위에서 값을 오른쪽으로 옮기는 계산이므로, 색에서는 항상 밝아지는 방향입니다.

`0.5` 회색에 `0.5`를 **곱하면** `0.25`가 되어 어두워집니다. `0`과 `1` 사이의 수끼리 곱하면 결과가 항상 더 작아지기 때문에, 색에서는 항상 어두워지는 방향입니다.

기억해 둘 성질이 두 가지 있습니다. 어떤 수에 `0`을 더하면 그대로이고, 어떤 수에 `1`을 곱하면 그대로입니다. 계산해도 값을 바꾸지 않는 이런 수를 **항등원**이라고 합니다. 색으로 말하면 검정을 더하면 변화가 없고, 흰색을 곱하면 변화가 없습니다.

빼기와 나누기 노드도 있지만, 빼기는 음수를 더하는 것이고 나누기는 역수를 곱하는 것입니다. 컴퓨터는 나누기보다 곱하기를 빨리 계산하므로 `2`로 나누는 대신 `0.5`를 곱하는 습관을 들이면 좋습니다.

### 05-6 색끼리의 연산

3차원 벡터인 색에도 `Add`와 `Multiply`를 쓸 수 있습니다. 이때는 빨강은 빨강끼리, 초록은 초록끼리, 파랑은 파랑끼리 따로 계산됩니다.

```text
(0.2, 0.5, 1.0) + (1.0, 0.5, 0.0) = (1.2, 1.0, 1.0)
(0.2, 0.5, 1.0) × (1.0, 0.5, 0.0) = (0.2, 0.25, 0.0)
```

더하면 밝아지고 곱하면 어두워진다는 성질은 그대로입니다. 하지만 세 값이 따로 움직이기 때문에 하늘색과 주황색을 더하면 무슨 색이 될지 머릿속으로 맞히기는 어렵습니다. 원하는 색을 계산으로 얻으려면 RGB보다 다루기 쉬운 표현이 필요합니다.

### 05-7 HSV 색상 모델

**HSV**는 색을 세 가지 성질로 나눠 표현하는 방법입니다.

| 글자 | 이름 | 의미 |
|---|---|---|
| H | 색상 | 빨주노초파남보 중 어느 색인가 |
| S | 채도 | 색이 얼마나 선명한가 |
| V | 명도 | 색이 얼마나 밝은가 |

색 선택 창의 둥근 색상환이 HSV 모델입니다. 색상환을 한 바퀴 도는 각도가 H이고, 화면에서는 `0`도에서 `360`도로 보이지만 머티리얼 안에서는 `0`에서 `1`로 정규화되어 있습니다. 반 바퀴는 `0.5`입니다.

HSV도 수 세 개이므로 3차원 벡터에 담습니다. RGB와 HSV 사이의 변환은 언리얼이 노드로 제공합니다.

| 노드 | 역할 |
|---|---|
| `RGBToHSV` | RGB 색을 HSV 값으로 바꾼다 |
| `HSVToRGB` | HSV 값을 RGB 색으로 되돌린다 |

최종 색에는 RGB를 넘겨야 하므로, 변환해서 계산한 뒤 반드시 다시 RGB로 돌려놓습니다.

색상환에서 자주 쓰는 색 조합입니다.

| 조합 | 색상환에서의 위치 | H에 더할 값 |
|---|---|---|
| 보색 | 정반대편, 180도 | `0.5` |
| 유사색 | 바로 옆, 30도 | `0.0833` |
| 삼각형 조화 | 정삼각형 꼭짓점, 120도 | `0.3333` |

### 05-8 보색 머티리얼 만들기

기준 색의 H 값만 꺼내 `0.5`를 더한 뒤 다시 합치면 보색이 됩니다. 벡터에서 일부만 꺼내고 다시 합치는 노드가 필요합니다.

| 노드 | 역할 |
|---|---|
| `ComponentMask` | 벡터에서 체크한 자리의 값만 남긴다 |
| `Append` | 두 값을 이어 붙여 차원을 늘린다 |
| `Frac` | 소수점 아래만 남긴다. `1.3`이면 `0.3` |

`ComponentMask`의 체크박스에는 R, G, B, A라고 적혀 있지만 색과는 관계없이 첫 번째, 두 번째, 세 번째, 네 번째 값을 뜻합니다. HSV 벡터에서 R에 체크하면 첫 번째 값인 H가 나옵니다.

순서대로 만들어 봅니다.

1. `3` + 클릭으로 기준 색 노드를 만들고 빨강으로 정한다.
2. `RGBToHSV` 노드에 연결한다.
3. `ComponentMask`를 만들어 R에만 체크하고 연결한다. H 값이 나온다.
4. `Add` 노드로 H에 `0.5`를 더한다.
5. `Frac` 노드에 연결한다.
6. `ComponentMask`를 하나 더 만들어 G와 B에 체크하고 `RGBToHSV`에 연결한다. S와 V가 나온다.
7. `Append` 노드의 A에 5번 결과를, B에 6번 결과를 연결한다.
8. `HSVToRGB` 노드에 연결하고 최종 색에 연결한다.

![보색 머티리얼 그래프: RGBToHSV → ComponentMask(R) → Add 0.5 → Frac → Append ← ComponentMask(GB) → HSVToRGB → 최종 색](./img/05-complementary-color-graph.png)

`Frac`이 필요한 이유는 H가 `0.8`인 색에 `0.5`를 더하면 `1.3`이 되어 범위를 벗어나기 때문입니다. 색상환은 한 바퀴 돌면 처음으로 돌아오므로 소수점 아래 `0.3`만 남기면 됩니다.

`Append`는 연결 순서가 중요합니다. A에 H, B에 SV를 넣어야 HSV 순서가 됩니다. 반대로 넣으면 SVH가 되어 엉뚱한 색이 나옵니다.

`Add`에 넣는 값을 `0.0833`이나 `0.3333`으로 바꾸면 유사색과 삼각형 조화색이 됩니다.

### 05-9 머티리얼 파라미터 컬렉션

보색, 유사색, 삼각형 조화 머티리얼을 따로 만들었다면, 기준 색을 바꿀 때마다 머티리얼을 하나씩 열어 고쳐야 합니다. 여러 머티리얼이 같은 값을 함께 쓰게 하려면 값을 머티리얼 밖에 따로 둡니다.

**머티리얼 파라미터 컬렉션**은 여러 머티리얼이 공유하는 값을 모아 둔 에셋입니다.

1. 콘텐츠 브라우저를 우클릭해 **머티리얼 → 머티리얼 파라미터 컬렉션**을 만든다.
2. 더블클릭해 열고 **벡터 파라미터**의 `+`를 누른다.
3. 파라미터 이름을 `Source`로 하고 기본값을 빨강으로 정한다.
4. 머티리얼 에디터에서 우클릭해 `collection`으로 검색하고 **컬렉션 파라미터** 노드를 만든다.
5. 노드를 선택하고 디테일 패널에서 방금 만든 컬렉션 에셋과 파라미터 이름 `Source`를 고른다.
6. 기준 색 노드 대신 이 노드를 `RGBToHSV`에 연결한다.

에셋 이름은 파라미터 컬렉션이고 그것을 쓰는 노드 이름은 컬렉션 파라미터라서 헷갈리기 쉽습니다. 이제 컬렉션 에셋에서 `Source` 색을 바꾸면 이 값을 쓰는 모든 머티리얼의 결과가 함께 바뀝니다.

### 05-10 따라하기 — 색 조합 머티리얼

1. User Interface 도메인 머티리얼에서 상수 값을 바꿔 검정, 회색, 흰색을 확인한다.
2. 색 두 개를 `Add`와 `Multiply`로 계산하고 `DebugFloat3Values`로 결과 숫자를 확인한다.
3. 보색 머티리얼을 만든다.
4. 같은 구조로 유사색 머티리얼과 삼각형 조화 머티리얼을 만든다.
5. 세 머티리얼의 기준 색을 머티리얼 파라미터 컬렉션의 `Source`로 바꾼다.
6. `Source`를 파랑으로 바꿔 세 머티리얼의 색이 함께 바뀌는지 확인한다.

시간에 따라 색이 변하는 머티리얼은 Chapter 06에서 만듭니다.

### 연습문제

1. 문제: 상수 노드 값이 `0`, `0.5`, `1`, `2`일 때 최종 색이 각각 무슨 색으로 보이는지 쓰세요.
2. 문제: `0.5` 회색에 `0.5`를 곱한 결과 값과, 색이 밝아지는지 어두워지는지 쓰세요.  
   - 조건: 결과 숫자를 포함할 것
3. 문제: H가 `0.7`인 색의 보색을 구할 때 `Frac` 노드가 필요한 이유를 계산 과정과 함께 쓰세요.  
   - 조건: 더한 결과 숫자와 `Frac`을 거친 숫자를 모두 쓸 것

### 정답 포인트

- `0`=검정, `0.5`=회색, `1`=흰색, `2`=흰색. `0.25`가 되어 어두워진다. `0.7 + 0.5 = 1.2`로 범위를 벗어나므로 `Frac`으로 `0.2`를 남긴다.
