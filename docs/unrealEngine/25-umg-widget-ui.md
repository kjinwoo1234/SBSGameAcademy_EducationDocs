# Chapter 25 UMG로 UI 만들기

## 학습 목표

- 위젯 블루프린트 에디터의 각 영역이 하는 일을 설명할 수 있다.
- 캔버스 패널의 앵커로 화면 크기가 바뀌어도 위치가 유지되는 UI를 배치할 수 있다.
- 프로그레스 바의 채우기 방식과 스타일을 바꿔 체력바를 만들 수 있다.
- 변수 바인딩과 델리게이트 두 가지 방법으로 체력바를 체력과 연동할 수 있다.

## 본문

### 25-1 위젯 블루프린트 에디터

Chapter 22에서 체력을 글자로 화면에 띄웠습니다. 이 장에서는 위젯 블루프린트를 제대로 다루어 체력바를 만듭니다.

콘텐츠 브라우저에서 **유저 인터페이스 → 위젯 블루프린트**로 `WBP_HealthBar`를 만들고 엽니다. 처음 열리는 화면이 **디자이너** 탭입니다.

![위젯 블루프린트 에디터 디자이너 탭에 번호로 표시한 메뉴 바·툴바·에디터 모드·팔레트·계층구조·비주얼 디자이너·디테일·애니메이션 영역](./img/25-widget-editor-layout.png)

| 영역 | 역할 |
|---|---|
| 툴바 | 컴파일, 저장, 플레이 버튼 |
| 에디터 모드 | 오른쪽 위에서 디자이너와 그래프를 전환한다 |
| 팔레트 | 화면에 놓을 수 있는 위젯 목록 |
| 계층구조 | 지금 놓인 위젯들의 부모와 자식 관계 |
| 비주얼 디자이너 | 실제 화면에 어떻게 보일지 배치하는 가운데 영역 |
| 디테일 | 선택한 위젯의 프로퍼티 |
| 애니메이션 | 위젯이 움직이거나 서서히 나타나는 효과를 만드는 타임라인 |

**그래프** 탭은 일반 블루프린트의 이벤트 그래프와 같습니다. 버튼을 눌렀을 때 할 일처럼 위젯의 동작을 만듭니다.

### 25-2 패널과 슬롯

위젯은 다른 위젯을 담을 수 있는 **패널**과 담기는 일반 위젯으로 나뉩니다. 패널 종류에 따라 자식을 배치하는 방식이 다릅니다.

| 패널 | 자식을 배치하는 방식 |
|---|---|
| 캔버스 패널 | 원하는 좌표에 자유롭게 놓는다 |
| 세로 박스 | 위에서 아래로 차례로 쌓는다 |
| 가로 박스 | 왼쪽에서 오른쪽으로 나란히 놓는다 |
| 그리드 패널 | 행과 열로 이루어진 표 칸에 넣는다 |
| 오버레이 | 같은 자리에 겹쳐 놓는다 |

패널에 위젯을 넣으면 그 위젯의 디테일 패널 맨 위에 **슬롯** 항목이 생깁니다. **슬롯**은 "부모 패널 안에서 내가 어떻게 놓일 것인가"를 담은 설정입니다. 부모가 캔버스 패널이면 위치와 크기가, 그리드 패널이면 몇 행 몇 열인지가 슬롯 항목에 나타납니다. 같은 위젯이라도 어느 패널에 들어가느냐에 따라 슬롯 내용이 달라집니다.

### 25-3 캔버스 패널과 앵커

팔레트에서 **캔버스 패널**을 디자이너로 끌어다 놓고, 그 위에 **텍스트**를 하나 놓습니다. 텍스트를 화면 오른쪽 위 구석으로 옮깁니다.

디자이너 오른쪽 위의 **화면 크기** 메뉴에서 다른 해상도를 골라 보세요. 화면이 넓어지면 텍스트가 구석에서 떨어져 가운데 쪽으로 밀려 보입니다. 위치가 화면 왼쪽 위를 기준으로 한 고정 좌표로 저장되어 있기 때문입니다.

**앵커**는 위젯의 위치를 화면의 어느 지점을 기준으로 잴지 정하는 기준점입니다. 디자이너에 꽃 모양 아이콘으로 표시됩니다.

1. 텍스트를 선택하고 디테일 패널의 **슬롯 → 앵커** 드롭다운을 연다.
2. 오른쪽 위 구석 모양을 고른다.
3. 텍스트를 다시 원하는 위치로 옮긴다.
4. 화면 크기를 바꿔 본다.

![앵커 프리셋 드롭다운과 캔버스 오른쪽 위 구석에 놓인 꽃 모양 앵커 아이콘](./img/25-anchor-presets.png)

이제 텍스트는 "화면 오른쪽 위에서 얼마만큼 떨어진 곳"으로 기억되어 화면 크기가 바뀌어도 구석에 붙어 있습니다.

| 놓을 UI | 어울리는 앵커 |
|---|---|
| 체력바 | 왼쪽 위 또는 왼쪽 아래 |
| 미니맵 | 오른쪽 위 |
| 조준점 | 가운데 |
| 대화창 | 아래쪽 가로로 늘이기 |

앵커 드롭다운 아래쪽의 늘이기 프리셋을 고르면 위젯이 화면 폭에 맞춰 함께 늘어납니다.

### 25-4 텍스트와 이미지

**텍스트** 위젯은 글자를 보여 줍니다. 디테일 패널의 **콘텐츠 → 텍스트**에 내용을 적고, **외형** 항목에서 색, 폰트, 크기, 외곽선, 그림자를 정합니다.

**이미지** 위젯은 그림을 보여 줍니다. 디테일 패널의 **외형 → 브러시 → 이미지**에 텍스처나 머티리얼을 지정합니다. Part 01에서 User Interface 도메인으로 만든 머티리얼을 여기에 넣으면 움직이는 무늬가 UI에 나타납니다.

| 브러시 프로퍼티 | 의미 |
|---|---|
| 이미지 | 보여 줄 텍스처 또는 머티리얼 |
| 이미지 크기 | 그림의 기본 크기 |
| 색조 | 그림에 곱해지는 색. 흰색이면 원래 색 그대로 |
| 그리기 유형 | 그림을 늘이는 방식. `Box`는 모서리는 그대로 두고 가운데만 늘인다 |

색조는 Chapter 05에서 배운 색의 곱하기입니다. 회색을 곱하면 그림이 어두워집니다.

### 25-5 프로그레스 바

**프로그레스 바**는 전체 중 얼마만큼 찼는지를 막대로 보여 주는 위젯입니다. 체력바, 로딩 표시, 경험치 표시에 씁니다.

1. 팔레트에서 **프로그레스 바**를 캔버스 패널에 놓는다.
2. 이름을 `HealthBar`로 바꾸고 **변수 여부**에 체크한다.
3. 앵커를 왼쪽 위로 정하고 크기를 가로 `300`, 세로 `30`으로 한다.
4. 디테일 패널의 **프로그레스 → 퍼센트**를 `0`에서 `1` 사이로 바꿔 본다.

| 프로퍼티 | 의미 |
|---|---|
| 퍼센트 | 찬 정도. `0`은 빈 상태, `1`은 가득 찬 상태 |
| 바 채우기 타입 | 차오르는 방향. 왼쪽에서 오른쪽, 오른쪽에서 왼쪽, 아래에서 위, 가운데에서 바깥 등 |
| 바 채우기 스타일 | 채움 그림을 줄이는 방식 |

바 채우기 스타일은 단색일 때는 차이가 없고, 무늬가 있는 그림을 쓸 때 드러납니다.

| 바 채우기 스타일 | 줄어드는 방식 |
|---|---|
| Mask | 그림을 잘라 낸다. 무늬가 제자리에 있고 보이는 범위만 줄어든다 |
| Scale | 그림 전체를 찌그러뜨린다. 무늬가 함께 좁아진다 |

기본 프로그레스 바는 밋밋합니다. 디테일 패널의 **스타일** 항목에서 겉모습을 바꿉니다.

5. 체력바로 쓸 가로로 긴 그림을 프로젝트에 임포트한다.
6. **스타일 → 배경 이미지 → 이미지**에 그 그림을 지정하고 **색조**를 어두운 회색으로 정한다.
7. **스타일 → 이미지 채우기 → 이미지**에 같은 그림을 지정하고 색조는 그대로 둔다.
8. 퍼센트를 바꿔 가며 결과를 확인한다.

![배경 이미지와 채우기 이미지를 지정한 프로그레스 바의 퍼센트 0.3·0.7·1.0 상태 비교](./img/25-progress-bar-style.png)

배경에 같은 그림을 어둡게 깔았기 때문에, 체력이 줄어든 부분이 어두운 그림으로 남아 보입니다.

### 25-6 C++에서 위젯 띄우기

Chapter 22에서는 블루프린트의 `Create Widget`으로 위젯을 띄웠습니다. C++에서 띄우려면 UI 모듈이 필요합니다. `Practice.Build.cs`의 모듈 목록에 `"UMG"`를 추가하고 에디터를 닫은 뒤 빌드합니다.

위젯은 플레이어 한 명의 화면에 속하므로 플레이어 컨트롤러에서 만드는 것이 자연스럽습니다. **툴 → 새 C++ 클래스**로 부모가 `PlayerController`인 `MyPlayerController`를 만듭니다.

```cpp
// MyPlayerController.h 의 클래스 안
protected:
	virtual void BeginPlay() override;

private:
	UPROPERTY(EditDefaultsOnly, Category = UI)
	TSubclassOf<class UUserWidget> HudClass;

	UPROPERTY()
	class UUserWidget* HudWidget;
```

```cpp
// MyPlayerController.cpp
#include "Blueprint/UserWidget.h"

void AMyPlayerController::BeginPlay()
{
	Super::BeginPlay();

	if (IsLocalController() && HudClass != nullptr)
	{
		HudWidget = CreateWidget<UUserWidget>(this, HudClass);
		if (HudWidget != nullptr)
		{
			HudWidget->AddToViewport();
		}
	}
}
```

**코드 해석**

- `TSubclassOf<UUserWidget>`은 "`UUserWidget`이거나 그 자식인 클래스"를 담는 타입입니다. 디테일 패널에서 위젯 블루프린트를 고를 수 있게 됩니다.
- `IsLocalController()`는 이 컨트롤러가 이 컴퓨터의 플레이어 것일 때만 참입니다.
- `CreateWidget<타입>(소유할 컨트롤러, 위젯 클래스)`로 위젯을 만들고 `AddToViewport()`로 화면에 올립니다.

빌드한 뒤 `MyPlayerController`를 부모로 블루프린트 `BP_MyPlayerController`를 만들어 **Hud Class**에 `WBP_HealthBar`를 지정합니다. 게임모드 블루프린트의 **플레이어 컨트롤러 클래스**를 `BP_MyPlayerController`로 바꾸면 플레이할 때 체력바가 나타납니다. Chapter 22에서 캐릭터 블루프린트에 넣었던 `Create Widget` 노드는 지웁니다.

### 25-7 변수 바인딩으로 체력 연결

체력바의 퍼센트를 캐릭터의 체력과 잇는 첫 번째 방법은 **바인딩**입니다. 프로퍼티에 함수를 묶어 두면, 위젯이 화면을 그릴 때마다 그 함수를 불러 값을 가져옵니다.

1. `WBP_HealthBar`의 디자이너에서 `HealthBar`를 선택한다.
2. 디테일 패널의 **퍼센트** 옆 **바인드** 드롭다운을 누르고 **바인딩 생성**을 고른다.

![프로그레스 바 디테일 패널에서 퍼센트 옆 바인드 메뉴가 열린 화면](./img/25-progress-bar-percent-bind.png)

3. 그래프 탭에 새 함수가 만들어진다. 함수 안에서 `Get Owning Player Pawn`을 캐릭터 클래스로 캐스트한다.
4. 캐릭터에서 `Health`와 `Max Health`를 꺼내 나누기 노드로 나눈다.
5. 나눈 값을 **Return Node**의 **Return Value**에 연결한다.
6. 캐스트가 실패했을 때는 `0`을 돌려주는 Return Node를 따로 연결한다.

체력은 `0`에서 `100`인데 퍼센트는 `0`에서 `1`이므로 현재 체력을 최대 체력으로 나눕니다. Chapter 05의 정규화와 같은 일입니다.

### 25-8 델리게이트로 체력 연결

바인딩은 간단하지만 체력이 변하지 않아도 매 프레임 함수를 부릅니다. 두 번째 방법은 체력이 바뀐 순간에만 체력바를 갱신하는 것입니다. Chapter 20과 22에서 쓴 델리게이트를 이번에는 블루프린트가 받을 수 있는 형태로 만듭니다.

```cpp
// MyCharacter.h — UCLASS() 위
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(FOnHealthChangedDelegate, float, Current, float, Max);

// 클래스 안
public:
	UPROPERTY(BlueprintAssignable, Category = Stat)
	FOnHealthChangedDelegate OnHealthChanged;
```

`TakeDamage`에서 체력을 바꾼 바로 다음 줄에 방송을 추가합니다.

```cpp
Health = FMath::Clamp(Health - FinalDamage, 0.0f, MaxHealth);
OnHealthChanged.Broadcast(Health, MaxHealth);
```

**코드 해석**

- `DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams`는 매개변수 두 개를 전달하는 다이내믹 델리게이트 타입을 만듭니다. 다이내믹 델리게이트는 타입과 이름을 쉼표로 나눠 적습니다.
- `BlueprintAssignable`은 블루프린트에서 이 델리게이트에 이벤트를 등록할 수 있게 하는 지정자입니다.

위젯 쪽에서 등록합니다. 먼저 25-7의 바인딩을 제거합니다. 퍼센트 옆 드롭다운에서 **바인딩 제거**를 누릅니다.

1. 그래프 탭에서 **Event Construct**를 만든다. 위젯이 만들어질 때 한 번 실행되는 이벤트다.
2. `Get Owning Player Pawn`을 캐릭터 클래스로 캐스트한다.
3. 캐스트 결과에서 `Bind Event to On Health Changed` 노드를 만든다.
4. 노드의 빨간 **Event** 핀을 드래그해 빈 곳에 놓고 **커스텀 이벤트 추가**를 고른다. `Current`와 `Max` 핀이 달린 이벤트가 만들어진다.
5. 커스텀 이벤트에서 `Current`를 `Max`로 나눈 값을 `HealthBar`의 `Set Percent` 노드에 연결한다.

![위젯 이벤트 그래프: Event Construct → 캐스트 → Bind Event to On Health Changed, 커스텀 이벤트에서 Current ÷ Max 를 Set Percent 에 연결](./img/25-widget-delegate-bind-graph.png)

| 방법 | 갱신 시점 | 특징 |
|---|---|---|
| 변수 바인딩 | 화면을 그릴 때마다 | 만들기 쉽다. 변화가 없어도 계속 계산한다 |
| 델리게이트 | 값이 바뀐 순간 | 필요한 때만 계산한다. 방송하는 코드가 필요하다 |

UI가 많아질수록 델리게이트 방식이 유리합니다.

### 25-9 따라하기 — 체력바

1. `WBP_HealthBar`에 캔버스 패널과 프로그레스 바를 놓고 앵커를 왼쪽 위로 정한다.
2. 배경 이미지와 채우기 이미지를 지정해 겉모습을 바꾼다.
3. `MyPlayerController`에서 위젯을 띄운다.
4. 변수 바인딩으로 체력을 연결하고, 맞았을 때 체력바가 줄어드는지 확인한다.
5. 바인딩을 제거하고 델리게이트 방식으로 바꾼다.
6. 체력 숫자를 보여 주는 텍스트를 체력바 옆에 추가하고 같은 커스텀 이벤트에서 갱신한다.
7. 화면 크기를 바꿔 체력바가 제자리에 붙어 있는지 확인한다.

혼자 플레이하는 상황에서는 플레이어 캐릭터가 맞을 일이 없습니다. 테스트를 위해 키 하나에 자기 자신에게 `ApplyDamage`를 호출하는 코드를 임시로 넣거나, Chapter 23의 적이 닿았을 때 데미지를 주게 만들어 확인합니다.

1. 문제: 조준점을 화면 한가운데에 고정하려면 앵커를 어디로 정해야 하는지 쓰고, 앵커를 왼쪽 위로 두었을 때 생기는 문제를 한 문장으로 쓰세요.
2. 문제: 프로그레스 바의 바 채우기 스타일 `Mask`와 `Scale`의 차이를 한 줄씩 쓰세요.
3. 문제: 체력이 `40`, 최대 체력이 `200`일 때 프로그레스 바의 퍼센트에 넣을 값을 계산하세요.  
   - 조건: 계산식을 함께 쓸 것

### 정답 포인트

- 가운데. 왼쪽 위 앵커면 화면 크기가 바뀔 때 가운데에서 벗어난다. Mask는 그림을 잘라 내고, Scale은 그림 전체를 찌그러뜨린다. `40 ÷ 200 = 0.2`.
