# Chapter 21 복사/이동 시맨틱

## 학습 목표
- 복사와 이동의 차이를 이해한다.
- Rule of 3/5 개념을 바탕으로 자원 소유 클래스를 안전하게 설계한다.

## 본문

### 21-1 복사 시맨틱
- 복사는 "같은 값을 가진 새 객체"를 만드는 동작입니다.
- 포인터 같은 자원 핸들을 얕게 복사하면 이중 해제 문제가 생길 수 있습니다.

### 21-2 이동 시맨틱
- 이동은 자원을 복사하지 않고 소유권을 옮겨 성능을 높이는 방식입니다.
- `std::move`는 "이 객체를 이동 대상으로 써도 된다"는 의도 표현입니다.
- 이동 생성자 인자 타입 `Buffer&&`에서 **`&&`**는 “잠깐 쓰다 없어질 값·이동해도 되는 쪽을 받는 **참조**”를 뜻합니다. 앞에서 배운 `Buffer&` / `const Buffer&`(**한 개 `&`**)는 살아 있는 이름을 붙인 객체용이고, `Buffer&&`(**두 개 `&`**)는 이동용으로 “가져가도 된다”는 쪽을 받을 때 씁니다. (이름은 **rvalue 참조**라고도 합니다. 지금은 “`&` = 별명, `&&` = 이동용 참조”만 기억해도 됩니다.)
- **`noexcept`**는 “이 함수는 예외를 던지지 않는다”고 컴파일러·호출자에게 알려 주는 표시입니다. 이동 생성자에 자주 붙여, 컨테이너가 이동을 더 적극 쓰게 돕습니다.
- **`explicit`**는 생성자가 **암시적 변환**에 쓰이지 않게 막는 표시입니다. `explicit Buffer(int v)`면 `Buffer b = 10;`처럼 숫자만으로 몰래 `Buffer`를 만드는 일을 막습니다.

### 21-3 Rule of 3/5
- 소멸자/복사 생성자/복사 대입이 필요하면 Rule of 3를 고려합니다.
- 이동 생성자/이동 대입까지 필요하면 Rule of 5를 적용합니다.

용어 설명:
| 용어 | 의미 |
|---|---|
| 시맨틱(semantic) | 코드 동작의 의미/의도 |
| 얕은 복사(shallow copy) | 포인터 주소만 복사해 같은 자원을 공유하는 복사 |
| 깊은 복사(deep copy) | 새 자원을 따로 확보해 내용까지 복사하는 방식 |
| `T&&` | 이동용 참조(rvalue 참조). 소유권을 넘길 때 인자로 자주 씀 |
| `noexcept` | 예외를 던지지 않겠다는 표시 |
| `explicit` | 생성자의 암시적 변환을 막는 표시 |

복사 vs 이동 비교:
| 항목 | 복사 | 이동 |
|---|---|---|
| 자원 처리 | 새 자원 복제 | 소유권 이전 |
| 비용 | 상대적으로 큼 | 상대적으로 작음 |
| 원본 상태 | 유지 | 유효하지만 비어 있을 수 있음 |

예시 코드:
```cpp
#include <iostream>
#include <utility>
using namespace std;

class Buffer {
public:
    int* data;
    explicit Buffer(int v) : data(new int(v)) {}
    ~Buffer() { delete data; }

    Buffer(const Buffer& other) : data(new int(*other.data)) {
        cout << "copy ctor\n";
    }
    Buffer(Buffer&& other) noexcept : data(other.data) {
        other.data = nullptr;
        cout << "move ctor\n";
    }
};

int main() {
    Buffer a(10);
    Buffer b = a;              // 복사
    Buffer c = std::move(a);   // 이동
    return 0;
}
```

예상 출력:
```text
copy ctor
move ctor
```

코드 해석:
- `Buffer b = a;`에서 복사 생성자가 호출되어 새 메모리를 확보합니다.
- `std::move(a)`는 `a`를 이동 가능 상태로 만들어 이동 생성자를 호출합니다.
- 이동 후 `a.data`를 `nullptr`로 바꿔 이중 해제를 방지합니다.
