# Chapter 2 혼자서 Git으로 버전 관리하기

## 학습 목표

- SourceTree로 기존 로컬 저장소를 열거나 새로 만든다.
- 스테이징·커밋·푸시를 GUI 흐름으로 수행한다.
- 커밋 그래프(히스토리)를 읽을 수 있다.

## 본문

<a id="ch2-1"></a>

### 2-1 로컬 저장소를 소스트리에 불러오기

SourceTree에서 **Add**와 **Clone**은 목적이 다릅니다. 이미 `git init`한 폴더는 **Add(로컬 저장소 추가)**입니다. 원격 URL에서 처음 받아 오려면 **Clone**입니다.

아래 순서로 연습 저장소를 SourceTree에 불러와 보세요.

1. SourceTree를 연 뒤 **Add** 또는 **Local**에서 폴더 추가를 선택합니다.
2. Chapter 0에서 만든 `my-first-repo`처럼 이미 `git init`한 경로를 지정합니다.
3. 왼쪽 또는 상단에 브랜치 이름과 파일 상태가 보이는지 확인합니다.
4. 원격이 비어 있으면 **Repository settings → Remotes**에서 나중에 `origin` URL을 추가할 수 있음을 확인만 합니다.

예상 결과:

```text
저장소가 목록에 추가되고, 현재 브랜치와 변경 파일 상태 패널이 보인다.
clone으로 받은 저장소와 달리 origin이 비어 있거나 없을 수 있다.
```

**절차 해석.** 클론은 보통 원격이 미리 잡혀 있고, 로컬만 init한 경우 원격을 수동 추가합니다.

<a id="ch2-2"></a>

### 2-2 소스트리로 커밋 만들고 푸시하기

변경 파일을 **스테이징(Stage)** 한 뒤 커밋 메시지를 작성하고 **Commit**합니다. 이어서 브랜치를 고르고 **Push**합니다. 첫 푸시는 upstream 설정이 필요할 수 있습니다. 커밋 메시지는 **무엇을·왜** 바꿨는지 한 줄로 요약하는 것을 권장합니다.

아래 GUI 순서로 커밋까지 해 보세요.

1. 연습 파일 하나를 수정하고 SourceTree **파일 상태**에서 변경을 확인합니다.
2. 커밋에 넣을 파일만 **Stage**합니다.
3. 메시지 칸에 요약을 쓰고 **Commit**을 누릅니다.
4. 원격이 연결되어 있으면 **Push**로 올립니다. 없으면 설정에서 `origin`을 추가한 뒤 푸시합니다.

예상 결과:

```text
히스토리에 새 커밋이 보이고, 스테이징할 변경이 비어 있다.
푸시에 성공하면 원격 브랜치와 커밋이 맞춰진다.
```

**절차 해석.** GUI의 Stage/Commit/Push는 아래 CLI와 같은 단계입니다. 같은 작업을 터미널에서 확인하려면 아래 명령을 실행해 보세요.

```bash
git add .
git commit -m "Describe change"
git push -u origin main
```

예상 결과:

```text
[main xxxxxxx] Describe change
 1 file changed, …
To …/REPO.git
   xxxxxxx..yyyyyyy  main -> main
```

**코드 해석.** `git add`가 Stage, `git commit`이 Commit, `git push -u`가 첫 Push와 upstream 설정에 대응합니다.

<a id="ch2-3"></a>

### 2-3 그림으로 Git 뜯어보기

**커밋 그래프**는 점(커밋)과 선(부모 관계)으로 시간 순 이력을 보여 줍니다. **브랜치 레이블**은 특정 커밋을 가리키는 **움직이는 포인터**입니다. **HEAD**는 지금 작업 중인 위치를 가리키며, 보통 브랜치 이름을 통해 가리킵니다.

| 용어 | 의미 |
|------|------|
| HEAD | 현재 체크아웃된 커밋 또는 그 브랜치를 가리키는 포인터 |

아래 순서로 그래프에서 갈라짐을 확인해 보세요.

1. SourceTree 히스토리 또는 그래프 화면을 엽니다.
2. 현재 `main`이 가리키는 최신 커밋을 찾습니다.
3. 새 브랜치를 만들고 그 브랜치에서 커밋 1개를 추가합니다.
4. 그래프에서 `main`과 새 브랜치가 갈라진 지점을 표시해 둡니다.

예상 결과:

```text
공통 조상 커밋에서 두 브랜치 라벨이 서로 다른 최신 커밋을 가리킨다.
HEAD는 새로 만든 브랜치 쪽에 있다.
```

**절차 해석.** 브랜치는 이름 붙은 커밋 포인터입니다. 병합 전까지 그래프가 갈라져 보이며, 병합·충돌은 [Chapter 3](./03-collaboration-sourcetree.md)에서 다룹니다.

### 연습문제

1. 문제: `git init`만 한 폴더와 `git clone`으로 받은 폴더를 SourceTree에 각각 추가하고, 원격 표시 차이를 적으세요.
   - 입력: init 폴더 1개, clone 폴더 1개
   - 출력: 원격 유무 차이를 적은 두 문장
   - 조건: 둘 다 SourceTree 목록에 추가할 것

2. 문제: 의도적으로 일부 파일만 스테이징하고 커밋한 뒤, 나머지 파일은 다음 커밋으로 나누세요.
   - 입력: 변경 파일 2개 이상
   - 출력: 커밋 2개. 각 커밋에 논리적으로 다른 변경
   - 조건: 한 번에 전부 스테이징하지 말 것

3. 문제: 새 브랜치에서 커밋 1개를 추가한 뒤, 그래프에서 `main`과 새 브랜치가 갈라진 지점을 설명하세요.
   - 입력: 새 브랜치 + 커밋 1개
   - 출력: 공통 조상과 두 포인터 위치를 설명하는 문장
   - 조건: SourceTree 그래프 또는 동등한 히스토리 화면을 보고 작성

### 정답 포인트

1. 클론은 보통 원격이 미리 있고, 로컬만 init하면 원격을 수동 추가한다.
2. 원자 커밋은 한 커밋에 한 논리적 변경을 담아 리뷰·되돌리기에 유리하다.
3. 브랜치는 이름 붙은 커밋 포인터이고, 병합 전까지 그래프가 갈라져 보인다.
