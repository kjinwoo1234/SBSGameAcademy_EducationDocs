# Chapter 04 데이터 표현방식의 이해

## 학습 목표

- **비트**와 **바이트**가 무엇인지, 자료형이 메모리를 얼마나 쓰는지 한 줄로 말할 수 있다.
- 실수가 **근사값**으로 저장될 수 있어 `==` 비교가 위험한 이유를 설명할 수 있다.
- 비트 연산자 `& | ^ ~ << >>`로 플래그를 켜고·끄고·검사할 수 있다.

## 본문

### 04-1 비트와 바이트

컴퓨터는 모든 데이터를 **0과 1**의 조합으로 저장합니다. 이 한 자리를 **비트**라고 부릅니다. 8비트가 모이면 **1바이트**가 되고, 자료형마다 사용하는 바이트 수가 달라집니다. 문자·숫자·이미지도 내부에서는 비트 패턴으로만 구분됩니다.

학습용으로 용량을 이어 보면, 1024바이트가 1KB, 1024KB가 1MB입니다. Windows + MSVC에서 자주 보는 크기의 예는 `char` 1바이트, `int` 4바이트, `float` 4바이트, `double` 8바이트 정도입니다. 자료형 종류를 더 넓게 정리하는 내용은 **다음 장**에서 이어집니다.

### 04-2 정수와 실수 표현

정수는 부호와 크기를 **정해진 비트 수** 안에 맞춰 저장합니다. 실수는 소수점을 포함한 값을 다루기 위해 **부동소수점** 규칙을 씁니다. 실수는 비트로 **정확한 값이 아니라 근사값**으로 저장되는 경우가 많습니다. 그래서 `0.1 + 0.2`가 우리가 기대하는 `0.3`과 비트 단위로 완전히 같지 않을 수 있습니다.

실무에서는 실수 동등 비교에 `==`만 쓰지 않고, 두 값의 차이가 아주 작은지 보는 **허용 오차** 방식이 안전합니다. `fabs` 같은 함수로 차이를 재는 패턴은 이후에도 자주 나옵니다. 입문에서는 “실수는 `==`로 딱 같다고 단정하기 어렵다”는 점만 확실히 잡으면 됩니다.
```c
#include <stdio.h>

int main(void)
{
    double x = 0.1 + 0.2;
    printf("%.17f\n", x);
    return 0;
}
```

**예상 출력** — 환경에 따라 끝자리가 조금 달라질 수 있습니다.

```text
0.30000000000000004
```

**코드 해석**

- `0.1 + 0.2`를 바로 `0.3`이라고 기대하면 안 되는 경우가 있습니다.
- `%.17f`로 소수 자리를 많이 찍으면 근사값 흔적이 보이기 쉽습니다.

`float`·`double`이 부호·지수·가수 비트로 나뉜다는 **큰 그림**만 알아 두면 충분합니다. 비트 칸 수를 외우거나 IEEE 754 공식을 손으로 전개하는 것은 이 장 필수 범위가 아닙니다.

### 04-3 비트 연산자

비트 연산은 정수를 **비트 단위**로 직접 다룹니다. 게임·임베디드·시스템 코드에서 상태 플래그를 압축해 둘 때 자주 등장합니다.

| 연산자 | 한 줄 뜻 |
|---|---|
| `&` | 두 비트가 모두 1일 때만 1 |
| `\|` | 하나라도 1이면 1 |
| `^` | 서로 다를 때 1 |
| `~` | 0과 1을 뒤집음 |
| `<<` | 비트를 왼쪽 이동. 보통 2배 방향 |
| `>>` | 비트를 오른쪽 이동. 보통 절반 방향 |

특정 비트를 켜려면 `flags |= (1 << n);`, 끄려면 `flags &= ~(1 << n);`, 켜져 있는지 보려면 `(flags & (1 << n)) != 0` 패턴을 씁니다. `unsigned char`는 **부호 없음**을 `char` 크기(1바이트)에 붙인 자료형입니다. 비트 여덟 자리를 플래그로 다루기 쉽게, 음수 없이 0~255 쪽만 쓰는 작은 정수 칸으로 보면 됩니다. `flags |= x`는 `flags = flags | x`이고, `flags &= x`는 `flags = flags & x`입니다.
```c
#include <stdio.h>

int main(void)
{
    unsigned char flags = 0;

    flags |= (1 << 0);
    flags |= (1 << 2);
    printf("flags: %u\n", flags);

    flags &= ~(1 << 0);
    printf("flags: %u\n", flags);

    printf("bit2 is on? %d\n", (flags & (1 << 2)) != 0);
    return 0;
}
```

**예상 출력**

```text
flags: 5
flags: 4
bit2 is on? 1
```

**코드 해석**

- bit0과 bit2를 켜면 `00000101` → `5`입니다.
- bit0을 끄면 `00000100` → `4`입니다.
- bit2가 켜져 있는지 `&`로 검사합니다.

부호 있는 타입의 오른쪽 시프트는 구현에 따라 주의가 필요합니다. 입문 연습은 `unsigned`나 양수 `int`로 시작하는 편이 안전합니다.

이 장 범위는 **비트·바이트 · 실수 근사 · 비트 연산 입문**입니다. 상수·자료형 표는 **다음 장**에서 이어집니다.

### 연습문제

**문제 1**

- 문제: `num = 12`일 때 `num << 1`, `num >> 1` 결과를 각각 출력하세요.
- 입력: 없음
- 출력: `24`, `6`
- 조건: `printf`로 확인

**문제 2**

- 문제: 정수의 3번째 비트(0부터 세면 bit2)를 ON으로 만드는 코드를 작성하세요.
- 입력: 정수 `num` 1개
- 출력: 비트 ON 적용 후 값
- 조건: `num |= (1 << 2);` 형태

**문제 3**

- 문제: 정수의 2번째 비트(bit1)가 켜져 있는지 검사하세요.
- 입력: 정수 `num` 1개
- 출력: 켜짐 여부 `1` 또는 `0`
- 조건: `(num & (1 << 1)) != 0` 형태

### 정답 포인트

- 문제 1: `12 << 1` → `24`, `12 >> 1` → `6`
- 문제 2: `num |= (1 << 2);`
- 문제 3: `(num & (1 << 1)) != 0`을 `%d`로 출력
- 공통: 비트 위치는 `1 << n`으로 만든다
