# Chapter 01 개론

## 학습 목표

- C언어가 무엇을 배우기 좋은지, 이 과정에서 무엇을 우선할지 한 줄로 말할 수 있다.
- **컴파일**이 소스(`.c`)를 실행 파일로 바꾸는 단계임을 설명할 수 있다.
- Windows에서 Visual Studio와 `cl`로 첫 C 프로그램을 빌드·실행할 수 있다.

## 본문

### 01-1 C언어와 학습 방향

C언어는 “컴퓨터에게 일을 시키는 방법”을 가장 기초부터 배우기 좋은 언어입니다. 다른 언어보다 **메모리**와 **주소**, 데이터가 저장되는 방식처럼 컴퓨터 내부 동작을 직접 다루기 때문에 처음에는 부담이 될 수 있지만, 한 번 몸에 익으면 이후에 실력이 단단해지는 편입니다. **메모리**는 프로그램이 실행되는 동안 숫자·글자 같은 값을 잠깐 넣어 두는 컴퓨터 안의 저장 공간이고, **주소**는 그 공간의 위치를 가리키는 번호에 가깝습니다. 세부 사용법은 뒤 챕터에서 다룹니다.

집을 지을 때 기초 공사가 중요하듯, C는 나중에 C++·C# 등을 배울 때도 받쳐 주는 **기초 체력**에 가깝습니다. 이 과정에서는 화려한 결과보다 **동작 원리를 정확히** 잡는 쪽에 초점을 둡니다.

C는 1970년대 초 시스템 소프트웨어를 위해 설계되었고, 운영체제·임베디드·드라이버·게임 엔진 코어처럼 **성능과 제어**가 중요한 곳에서 많이 쓰입니다. 학습 관점에서는 “컴퓨터가 실제로 어떻게 동작하는지”를 이해하는 출발점으로도 좋습니다.

### 01-2 컴파일이란

**컴파일**은 사람이 읽기 쉬운 **소스 코드**(보통 `.c` 파일)를 컴퓨터가 실행할 수 있는 형태(Windows에서는 보통 `.exe`)로 바꾸는 과정입니다. 사람의 글을 컴퓨터가 이해하는 형태로 **번역**한다고 보면 됩니다.

일반적인 흐름은 **코드 작성 → 컴파일 → 실행**입니다. C는 실행 전에 컴파일이 필요하고, 문법이 틀리면 오류 메시지가 나오며 실행 파일이 만들어지지 않을 수 있습니다.

### 01-3 Visual Studio와 `cl`

**Visual Studio**는 Microsoft가 제공하는 프로그래밍용 **IDE**입니다. IDE는 Integrated Development Environment의 줄임말로, 코드 작성·빌드·실행·오류 확인·디버깅을 한 화면에서 이어 가기 쉽게 묶어 둔 **통합 개발 환경**입니다. 이 과정에서는 코드를 쓰는 자리이자, MSVC 컴파일러를 설치·사용하는 중심 도구입니다.

**`cl`**은 Visual Studio에 포함된 C/C++ 컴파일러 **MSVC**를 명령줄에서 실행할 때 쓰는 프로그램 이름입니다. `main.c` 같은 소스를 읽어 실행 가능한 프로그램으로 만듭니다. 컴파일이 끝나면 같은 폴더에 `main.obj` 같은 중간 결과와 `main.exe` 같은 실행 파일이 생기는 경우가 많습니다.

컴파일러마다 옵션과 오류 문구가 조금 다를 수 있으므로, 이 문서는 **Windows + Visual Studio + `cl`** 기준으로 맞춥니다.

대부분 Visual Studio는 빌드 버튼을 누를 때 내부에서 `cl` 같은 도구를 대신 호출합니다. 매번 명령어를 치지 않아도 학습은 가능합니다. 다만 오류가 났을 때 환경 문제인지 코드 문제인지 가르려면, **컴파일러가 소스를 실행 파일로 바꾼다**는 그림만 알아 두면 충분합니다.

### 01-4 개발 환경 세팅

이 문서는 **Windows + Visual Studio + MSVC(`cl`)** 조합을 기준으로 합니다. 이 장에서는 환경을 준비하는 것까지가 목표입니다. 첫 `.c` 파일의 구조와 화면 출력은 **다음 챕터**에서 다룹니다.

1. **Visual Studio Installer 준비**  
   Visual Studio Community를 설치합니다. 이미 있으면 시작 메뉴에서 **Visual Studio Installer**만 열어도 됩니다.

2. **C/C++ 워크로드 선택**  
   Installer에서 제품을 고른 뒤 **수정(Modify)**을 누릅니다. **Desktop development with C++** 워크로드를 체크하고, 요약에 `MSVC`, `Windows SDK` 등이 보이는지 확인한 다음 설치를 마칩니다. 이 단계를 빼먹으면 `cl`이 인식되지 않는 경우가 많습니다.

3. **Developer PowerShell 실행**  
   시작 메뉴에서 **Developer PowerShell for VS 2022**를 엽니다. 일반 PowerShell이 아니라 Visual Studio가 준비한 **개발자용 셸**을 써야 `cl` 경로가 잡히는 경우가 대부분입니다.

4. **컴파일러 확인**  
   개발자 PowerShell에서 `cl`만 입력합니다. 버전·사용법 안내가 오류 없이 나오면 설치가 정상인 경우가 많습니다.

5. **인식이 안 될 때**  
   워크로드가 실제로 설치됐는지, 개발자용 셸인지, 설치 직후 터미널을 다시 열었는지 확인합니다. 그래도 안 되면 PC를 재부팅한 뒤 다시 시도합니다.

### 01-5 첫 C 프로그램 작성·실행

프로젝트용 폴더를 만들고 그 안에 `main.c`를 둡니다. 아래는 그 파일에 넣을 수 있는 최소 예시입니다.

아래에는 `#include`, `int main`, `return` 같은 낯선 단어도 보입니다. **지금은 뜻을 전부 외울 필요 없습니다.** “C 콘솔 프로그램의 **기본 뼈대**가 이렇게 생겼다”고만 보고, 우리가 고칠 곳은 `main`의 `{` `}` **안**이라고 생각하면 됩니다. `#include`와 전처리기 세부, `main`의 구조는 **다음 장**에서 이어집니다.

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, C!\n");
    return 0;
}
```

**예상 출력**

```text
Hello, C!
```

**코드 해석**

- `#include <stdio.h>`는 화면 출력에 쓰는 기능을 가져오는 줄입니다. 지금은 **지우지 말고** 둡니다.
- `main`의 `{` `}` 안이 실제로 실행되는 부분입니다.
- `printf("Hello, C!\n");`가 콘솔에 문장을 보여 줍니다. `\n`은 **줄바꿈**입니다.
- `return 0;`은 프로그램이 정상 종료했음을 알리는 관례적인 줄입니다.

**CLI로 컴파일·실행하기**

**Developer PowerShell for VS 2022**에서 `main.c`가 있는 폴더로 이동한 뒤, 컴파일하고 실행합니다. `cd` 뒤 경로는 **본인 PC에 `main.c`를 둔 실제 경로**로 바꿉니다.

```text
cd D:\예시폴더\내프로젝트
cl main.c
.\main.exe
```

| 목적 | 예시 명령 | 결과 |
|---|---|---|
| 기본 컴파일 | `cl main.c` | 보통 `main.exe` |
| 실행 파일 이름 지정 | `cl /Fegreet.exe main.c` | `greet.exe` |
| 경고를 더 보기 | `cl /W4 main.c` | 경고 수준을 높임 |

`.\main.exe`의 `.\`는 PowerShell에서 **지금 폴더**의 프로그램을 실행한다는 뜻입니다. 화면에 `Hello, C!`가 보이면 환경이 정상인 경우가 많습니다. `cl`을 찾을 수 없다면 **01-4**의 개발자 셸·워크로드를 다시 확인합니다.

**Visual Studio에서 실행하기**

솔루션·프로젝트를 연 뒤 **빌드**한 다음, **디버그하지 않고 실행**(보통 `Ctrl + F5`)합니다. 같은 문구가 콘솔에 보이면 CLI와 같은 목표를 달성한 것입니다.

이 장에서는 **환경 준비**와 **첫 출력 한 줄**에만 집중합니다. `printf`를 더 자세히 쓰는 법, 변수·입력은 **이후 장**에서 이어집니다.

### 연습문제

**문제 1**

- 문제: `Hello, C!` 대신 본인 이름이 나오도록 `printf` 문자열만 바꿔 출력하세요.
- 입력: 없음
- 출력: 이름이 포함된 한 줄
- 조건: `printf`의 큰따옴표 안 글자만 변경

**문제 2**

- 문제: `\n`을 사용해 서로 다른 문장 3줄을 출력하세요.
- 입력: 없음
- 출력: 문장 3줄
- 조건: `printf`를 한 번 또는 여러 번 사용 가능

**문제 3**

- 문제: 같은 소스를 CLI(`cl`)와 Visual Studio(`Ctrl + F5`)로 각각 한 번 이상 실행하세요.
- 입력: 없음
- 출력: 두 방식 모두 같은 결과 화면
- 조건: 결과가 다르면 저장 파일·빌드 대상을 먼저 확인

### 정답 포인트

- 문제 1: `printf("...");` 안 문자열만 원하는 이름으로 바꾼다.
- 문제 2: 문자열 안에 `\n`을 넣거나 `printf`를 여러 번 쓴다.
- 문제 3: 같은 `main.c`를 두 경로로 실행해 문구가 같으면 된다.
- 공통: 고칠 곳은 `main`의 `{` `}` 안 `printf` 줄뿐이다.
