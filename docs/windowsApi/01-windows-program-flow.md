# Chapter 01 윈도우 프로그램이 움직이는 방식

## 학습 목표

- 콘솔 프로그램과 창이 있는 Windows 프로그램의 차이를 말로 구분할 수 있다.
- Win32에서 “창 만들기 → 메시지 받기 → 그리기” 흐름을 순서도로 설명할 수 있다.
- 이 과정에서 API를 전부 외우지 않고 **동작 원리**를 목표로 함을 말할 수 있다.

## 본문

### 01-1 왜 Win32를 배우나

콘솔 프로그램은 검은 창에 글자를 출력하고, `main`이 끝나면 끝나는 경우가 많습니다.  
게임이나 도구처럼 **창이 뜨고, 마우스를 누르고, 화면이 다시 그려지는** 프로그램은 Windows가 “무슨 일이 생겼는지”를 **메시지**로 알려 주고, 우리가 그 메시지에 반응하는 구조입니다.

그 기본 층을 다루는 것이 **Win32 API**입니다. 게임 개발을 한다면 API를 실무 수준으로 전부 외울 필요는 없습니다. **창·메시지·입력·타이머가 어떻게 이어지는지**를 이해하는 것이 목표입니다. 그 이해가 나중에 DirectX·엔진의 “윈도우 핸들”을 볼 때 도움이 됩니다.

| 구분 | 콘솔 | Win32 창 프로그램 |
|------|------|-------------------|
| 시작 함수 | 보통 `main` | 보통 `WinMain` |
| 화면 | 텍스트 위주 | 창 + 그림·컨트롤 |
| 입력 처리 | `cin` 등 | 메시지(`WM_KEYDOWN` 등) |

### 01-2 한 번에 보는 뼈대

Win32 창 프로그램은 대략 아래 순서로 움직입니다.

```text
WinMain()
    ↓
WNDCLASS 채우기
    ↓
RegisterClass()
    ↓
CreateWindow()
    ↓
ShowWindow() / UpdateWindow()
    ↓
메시지 루프
    GetMessage → TranslateMessage → DispatchMessage
    ↓
WndProc()   ← 여기서 메시지별 처리
```

**윈도우 클래스**는 “이런 종류의 창은 이렇게 동작한다”는 **설계도**에 가깝습니다.  
**창**은 그 설계도로 실제로 만든 **한 장의 창**입니다.  
**메시지 루프**는 Windows가 보낸 일을 계속 꺼내 `WndProc`에 넘기는 **반복**입니다.

| 이름 | 한 줄 뜻 |
|------|----------|
| `WinMain` | 창 프로그램의 시작 함수 |
| `WNDCLASS` | 창 종류에 대한 설정 묶음 |
| `CreateWindow` | 실제 창을 만듦 |
| 메시지 루프 | 이벤트를 받아 처리하는 반복 |
| `WndProc` | 메시지마다 할 일을 적는 함수 |

### 01-3 이 과정에서 갈 길

앞으로 장은 이 순서를 따릅니다.

```text
① 기본 구조(창·루프·WndProc)
② 메시지 종류
③ GDI로 그리기
④ 키보드·마우스
⑤ 메뉴·버튼
⑥ 타이머
⑦ 작은 게임
⑧ 데이터·리소스
⑨ DirectX로 넘어갈 준비
```

지금은 **①의 전체 지도**만 잡으면 됩니다. 각 API의 매개변수는 **다음 장들**에서 하나씩 엽니다.
