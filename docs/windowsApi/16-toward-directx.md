# Chapter 16 DirectX로 넘어가기

## 학습 목표

- Win32에서 배운 창·메시지·입력이 DirectX에서도 왜 필요한지 말할 수 있다.
- GDI와 Direct3D의 역할 차이를 구분할 수 있다.
- 게임 개발 관점에서 다음 학습 순서를 스스로 정할 수 있다.

## 본문

### 16-1 Win32가 남겨 주는 것

이 과정에서 다룬 핵심은 다음과 같습니다.

```text
Win32
 │
 ├─ Window        (HWND, CreateWindow)
 ├─ Message       (루프, WndProc)
 ├─ Input         (키·마우스 메시지)
 ├─ Timer         (또는 더 정밀한 루프)
 └─ HDC / GDI     (2D 그리기 입문)
```

게임을 본격적으로 그리기 시작하면 보통 **GDI 대신 DirectX**를 씁니다. 그래도 **창을 만들고 메시지를 받는 층**은 Win32에 남는 경우가 많습니다. Direct3D 장치 생성에도 `HWND`가 필요합니다.

### 16-2 GDI에서 DirectX로

| 구분 | GDI | DirectX |
|------|-----|---------|
| 목적 | OS 기본 2D 그리기 | 게임·고성능 그래픽 |
| 그리기 | `HDC`, `Rectangle` 등 | Direct3D 파이프라인 |
| 입문 가치 | 창·페인트 원리 이해 | 실제 게임 렌더링 |

추천 흐름입니다.

```text
Win32 API
   ↓
Windows 구조 이해   ← 지금 여기
   ↓
DirectX 11
   ↓
DirectX 12 (필요 시)
   ↓
게임 엔진
```

엔진을 먼저 써도 되지만, “엔진이 숨긴 윈도우·메시지”를 한번 보면 디버깅이 쉬워집니다.

### 16-3 다음에 만들면 좋은 것

Win32를 더 연습하고 싶다면:

1. **그림판** — 마우스 + GDI
2. **벽돌깨기** — 타이머 + 충돌 + 여러 객체
3. **2D 슈팅** — 탄·적·상태 관리

그래픽을 올리려면 같은 `HWND` 위에 Direct3D 스왑 체인을 붙이는 튜토리얼로 넘어가면 됩니다. 입력은 당분간 Win32 메시지를 그대로 써도 되고, 나중에 XInput 등으로 패드를 확장합니다.

이 장에는 새 API 실습이 없습니다. **지도와 다음 갈림길**을 확인하는 장입니다.
